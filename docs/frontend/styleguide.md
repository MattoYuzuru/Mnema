# Стайлгайд frontend

Живой каталог дизайн-системы Mnema — маршрут `/styleguide`. Каждый пример на нём — настоящий компонент
или класс приложения, а не копия. Визуальное направление и токены описывают
[design and experience](./design-and-experience-2026-09.md) и
[brand and UI contract](./mnema-brand-and-ui-contract.md); этот документ — про то, как ими пользоваться.
Исполняемые примеры находятся в `frontend/src/theme/tokens.css`,
`frontend/src/theme/components.css`, `frontend/src/app/shared/`. При расхождении с
принятым design-контрактом проверь причину и исправь канонический источник: код
сам по себе не отменяет принятую визуальную границу.

## Правила

1. **Бери из стайлгайда.** Для кнопки, сообщения, подсказки, поля, метки, пустого состояния, листа нужен класс или компонент из каталога.
   Не рисуй свой вариант в стилях страницы и не копируй чужой: страница добавляет только раскладку
   (`.actions .button { flex: 1 1 12rem }`), а не второй вид элемента.
2. **Новый элемент — сначала в стайлгайд.** Нужно то, чего в каталоге нет: добавь пример и подпись «когда использовать»
   на страницу `/styleguide`, затем используй на экране. Если элемент общий, он живёт в `src/theme/components.css`
   (простые классы) или `src/app/shared/` (компоненты с поведением), а не в файле одной страницы.
3. **Только токены.** Цвета, отступы и радиусы — `--mn-*`. Hex, `px`-радиусы и теневые наборы в стилях компонентов не добавляются.
4. **Один главный приём на экран.** `.generate-cta` не больше одного. Удержание (`app-hold-to-delete-button`) — для необратимого удаления
   **и** досрочного завершения знакомства (тур): первое нажатие взводит кнопку, жест держится заданное время (3 с у удаления, 2 с у завершения),
   Esc, уход фокуса и нажатие вне кнопки снимают взвод. Другого «опасного» или «подтверждающего» жеста нет.
5. **Доступность — часть примера.** Область нажатия не меньше `--mn-touch-min`, фокус виден, статус назван словами,
   `forced-colors` и reduced motion не ломают смысл. Пример, не проходящий это, не попадает в каталог.

Тёмной темы и режимов плотности в продукте нет: страница не имеет их переключателей и честно об этом говорит.
Для движения есть переключатель «Спокойное движение»: он показывает вид страницы при reduced motion независимо от системной настройки.

## Длинные списки и автоподгрузка

Для длинных списков контента принят infinite scroll с опережающей загрузкой. Сетевой API остаётся
пагинированным: ограниченная порция, стабильный курсор, проверка контекста/ревизии. В интерфейсе нет
обычных кнопок «Показать ещё», номеров страниц или предыдущей/следующей страницы. Пользователь
читает и прокручивает один непрерывный список. Это правило действует для материалов, библиотеки
колод, упражнений материала, Capture, прогресса Study, уведомлений, событий, мастерских и списков кабинета
владельца (пользователи, промокоды, очередь обращений, журналы, сообщения тикета; общий помощник `features/admin/cursor-list.ts`).

Общий элемент — `shared/auto-load.component.ts` (`app-auto-load`); исполняемый пример со своей
прокруткой и имитацией сетевой ошибки находится в разделе «Обратная связь» `/styleguide`.

- Передайте `content` — DOM-элемент именно списка, `continuation` — следующий курсор, `loading`,
  `error`, а в `(loadNext)` подключите загрузку. Для отдельного scroll-контейнера задайте `root`;
  скрытый popover отключайте через `enabled`.
  При полной замене snapshot с сохранением того же DOM/курсора меняйте `context`; это явное начало нового списка,
  а повторившийся курсор обычного ответа сам по себе не запускает бесконечную цепочку запросов.
- Запас наблюдателя — 25% текущей высоты списка. Следующая порция запрашивается, когда нижний край
  viewport достигает примерно 75% загруженного содержимого. Для короткого списка запас не меньше
  одного viewport, чтобы заполнить доступное место. Высота пересчитывается после подгрузки,
  изменения ширины и увеличения текста. Статистика и заголовки вне списка на порог не влияют.
- Владелец данных допускает один запрос, добавляет строки по стабильному id без дублей, отменяет
  или игнорирует ответ старого контекста. На конце (`continuation = null`) запросов больше нет.
- Подгрузка сохраняет строки, выбор и текущий фокус. Статус загрузки озвучивается через `role=status`.
  Ошибка сохраняет прочитанное, останавливает автоповторы и показывает единственную кнопку «Повторить».
  Во время повтора кнопка остаётся на месте (`aria-disabled`), а после успешного повтора с клавиатуры фокус переходит
  на первую новую строку. Владелец, который перезагружает список, держит старые строки до ответа и меняет `context`.
- Подвал страницы за бесконечным списком доступен через вторую skip-ссылку оболочки «К подвалу: документы и поддержка».
- В хабе материалы загружаются по 50. Порция — параметр конкретного списка в пределах API,
  а не причина сразу скачивать всю колоду. Для длинных рядов используйте браузерную отсрочку
  отрисовки невидимого содержимого или обоснованную виртуализацию, с проверкой клавиатуры,
  выбора, фокуса, enlarged text и фактической геометрии в браузере. DOM и accessibility identity
  строк хаба сохраняются; `content-visibility: auto` сокращает работу layout/paint вне viewport.
  Резервная intrinsic-высота учитывает content box; декорация/tail/панель действий исключены из scroll anchoring.
  Браузерная проверка сравнивает положение читаемого материала до/после добавления страницы, а не только `scrollY`.

Пейджер партии генерации и переход между отдельными объектами выбирают рабочий объект;
они сохраняются. Их не следует использовать для продолжения каталога.

Решения опираются на [Angular afterRenderEffect](https://angular.dev/api/core/afterRenderEffect)
(наблюдатели устанавливаются после render и снимаются с контекстом),
[Intersection Observer](https://www.w3.org/TR/intersection-observer/)
(опережение задаётся `rootMargin` в px, рассчитанным из высоты списка) и
[CSS Containment](https://www.w3.org/TR/css-contain-2/#content-visibility)
(невидимое содержимое можно пропускать при layout/paint, сохраняя доступность при `auto`).
Декорация исключается из anchoring по [CSS Scroll Anchoring](https://www.w3.org/TR/css-scroll-anchoring-1/#exclusion-api),
чтобы изменение высоты страницы удерживало читаемый материал, а не звёзды на её полях.

## Как открыть

В полном локальном стеке включите development-сборку frontend, сохраняя текущие
аккаунты, материалы, сертификаты и порты:

```bash
MNEMA_LOCAL_FRONTEND_CONFIGURATION=development ./scripts/mnema-local-full-stack.sh start
```

Откройте [Style Guide в локальном стеке](https://localhost:3443/styleguide) (если при
bootstrap выбран другой `MNEMA_LOCAL_WEB_PORT`, используйте этот сохранённый порт).
Это тот же runtime, а не второй набор данных. На следующих `start` повторяйте флаг,
пока нужен каталог. Для возврата к production-сборке:

```bash
./scripts/mnema-local-full-stack.sh start
```

Только каталог без Docker/backend можно открыть отдельным dev-сервером:

```bash
(cd frontend && npx ng serve --host 127.0.0.1 --port 4200)
```

[Style Guide без backend](http://localhost:4200/styleguide) использует локальные
фикстуры и не требует входа. `npm start` в проекте нет; цель `serve` в
`frontend/angular.json` по умолчанию собирает `development`. Остановите dev-сервер
через Ctrl+C.

Фикстуры исполняемых образцов лежат внутри `frontend/`: Docker release собирает
только этот каталог. Импортировать соседние `contracts/` из компонентов нельзя,
даже если стайлгайд затем удаляется из production-бандла: TypeScript сначала
разрешает импорты. Общий wire fixture можно импортировать в `*.spec.ts` для
проверки соответствия локального образца контракту.

Production и обычный локальный `start` отдают production-сборку (`npm run build`),
поэтому `/styleguide` там **нет**. Флаг работает только с
`deploy/local-full-stack/frontend.Dockerfile` и допускает `development` или
`production`; release Dockerfile его не использует. Это следует Angular
[build configurations](https://angular.dev/tools/cli/environments) и Docker
[build arguments](https://docs.docker.com/build/building/variables/).
Подробнее о данных и портах: [локальный runtime](../deploy/selfhost-local.md).

## Почему страницы нет в production

`app.routes.ts` регистрирует маршрут только при `typeof ngDevMode === 'undefined' || ngDevMode`. Сборщик приложения Angular
в конфигурации `production` (`optimization.scripts`) определяет `ngDevMode` как `false`, esbuild убирает условие вместе с
динамическим `import()`, и ни маршрут, ни чанк страницы в бандл не попадают. `isDevMode()` — вызов времени выполнения и код бы оставил.

Проверка выходного каталога после `npm run build`:

```bash
cd frontend
node scripts/verify-no-styleguide.mjs              # dist/mnema-frontend; exit 0 — страницы нет
npx ng build --configuration development && node scripts/verify-no-styleguide.mjs   # обязан упасть: проверка честная
```

Скрипт ищет в файлах сборки имя `styleguide`, компонент и русские тексты страницы. Юнит-тест `app.routes.spec.ts`
фиксирует, что в development-сборке маршрут есть, ленивый и без `canActivate`.

Контакт поддержки берётся из `appConfig.supportTelegramUsername`; текущий публичный
бот — `Mnema_Support_Bot`. Контейнер может переопределить имя через
`MNEMA_SUPPORT_TELEGRAM_USERNAME` без изменения сборки. Допускается только имя бота
в формате BotFather (5–32 латинских символа, цифры или `_`, окончание `bot`);
ссылка строится на `https://t.me/`. Для отсутствующего или некорректного контакта
компонент показывает пояснение без ссылки. SVG-знак оригинальный, `aria-hidden`,
смысл и указание новой вкладки передаёт текст ссылки. Контакт по почте `app-mail-contact` не печатает адрес: `mailto:` собирается из частей в
`shared/legal-operator.ts` при нажатии; политика и соглашение показывают адрес текстом и ссылкой.
Реквизиты футера предоставлены
владельцем; изменения этих сведений требуют проверенных данных, а не копирования референса.

### Блок публикации и панель доступа

Заголовки: `.section-heading` у `h2` раздела блока, `.subsection-heading` у `h3` его частей (`components.css`); `h2` всегда крупнее `h3`.

Хаб колоды открывает доступ и публикацию кнопкой «Поделиться» со знаком текущего уровня доступа:
замок, приглашение, ссылка или публичная колода. Общий `app-paper-dialog` — нативный модальный `<dialog>`
на бумажном фоне, заголовок, прокручиваемое содержимое и «Готово». Esc закрывает окно, фокус возвращается
к открывшей кнопке; при открытии уведомления с `#access` фокус после закрытия идёт к «Поделиться».
Состояние `app-publication-block` остаётся смонтировано при закрытии: ошибки, неподтверждённая команда
и показанная один раз пригласительная ссылка не теряются. Постоянного раздела на странице нет.

- **Выбор уровня** (`app-access-controls`) сохраняет «Приватная», «По ссылке» и «По приглашению» сразу
  при выборе. Во время запроса выбор занят, а при неизвестном исходе заблокирован до «Повторить» той же команды.
  До выбора видны последствия смены ссылки. Публичность по-прежнему требует серверного чек-листа и отдельного
  действия публикации: обычный выбор не обходит проверку условий и наполнения колоды.
- **Переключатель «Принимать запросы доступа»** — `.settings-row.is-switch.is-live`; сохраняется тем же `PUT`, во время сохранения `aria-disabled`.
- **Панель доступа** (`app-access-panel`, только у «По приглашению») — три независимых раздела, у каждого свой заголовок, загрузка и повтор:
  «Запросы доступа» (человек, дата, «Принять» / «Отклонить»; отказ тихий), «Пригласительные ссылки» (форма «Сколько раз» и «Срок» на
  `app-mnema-select`, «Создать ссылку»; новая ссылка показана **один раз**, вместо формы, группой `notice warning` с описанием «Ссылка показана один раз…» (фокус переходит на группу, скринридер читает его); в списке ссылки и токена нет,
  у действующей «Отозвать»; «Устарела» — ссылка более раннего поколения кода, после понижения уровня, без действия) и «Кто имеет доступ» (люди, «Закрыть доступ», «Пригласить по логину»: только владельцы публичного профиля, неизвестный
  и скрытый читаются одинаково).
- **Строка `.roster-row`** (`components.css`) — общий вид строки списка людей, запросов и ссылок: имя и факты слева (`.roster-main`), действия справа
  (`.roster-actions`), перенос на узком экране. Кнопка строки начинается с видимого слова и добавляет, о ком она (`aria-label="Принять запрос от @anna.k"`, WCAG 2.5.3), когда имя уже известно; список — `role="list"`, пустой список показывает фразу вне списка.
  Человек показан чипом автора `app-author-chip` через Identity (`AuthorCardsService`, пачки до 50); без публичной карточки — «Пользователь без
  публичного профиля». После ухода строки (решён запрос, закрыт доступ, отозвана ссылка) фокус идёт к заголовку раздела, а не к соседней разрушающей кнопке;
  результат озвучивает вежливый `role=status`. Сбой загрузки имени даёт маленькую кнопку «Повторить». Списки подгружаются `app-auto-load`, без кнопок «Показать ещё».

### Выбор из сегментов в режиме forced-colors

`app-segmented-choice`: выбранный сегмент не должен зависеть от заливки `Highlight`. Chrome подкладывает под такой текст подложку Canvas, и подпись
`HighlightText` превращалась в белый прямоугольник. В `forced-colors` все подписи `ButtonText` на `Canvas`, выбор показывают закрашенный кружок
(`Highlight`) и контур `Highlight`; контракт закреплён в `segmented-choice.css.spec.ts`, вид проверен в Chrome с эмуляцией `forced-colors: active`.

### Меню действий «⋯» и «Поделиться»

- **`app-action-menu`.** Кнопка «⋯» и меню по шаблону [APG menu button](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/):
  `aria-haspopup="menu"`, `aria-expanded`, `aria-controls`, имя задаёт вызывающий («Действия с колодой «…»»). Меню — нативный
  `popover="auto"` ([MDN Popover API](https://developer.mozilla.org/docs/Web/API/Popover_API)): верхний слой, закрытие кликом вне и
  Esc. Enter, Пробел и ↓ открывают меню и ставят фокус на первый пункт, ↑ — на последний; ↑ ↓ (по кругу), Home, End и буква
  ходят по пунктам (та же буква ещё раз — следующий такой пункт); Esc и выбор пункта возвращают фокус на кнопку, Tab закрывает меню. Недоступные пункты пропускаются. Вход:
  `label`, `items` (`id`, `label`, `glyph?`, `disabled?`, `danger?`), выход `chosen` с `id`. Возле кнопки меню ставит CSS anchor
  positioning, без него браузер центрирует его в окне (как у `app-toggletip`). В меню только действия, которые уже работают (в хабе колоды: «Доступ…», у копии ещё «Отвязать от автора»).
- **«Поделиться».** `ShareLinkService.share(url, title)` вызывается прямо из обработчика клика (нужна активация пользователя).
  На телефоне (`(pointer: coarse)`, `navigator.share`, `canShare({ url })`) открывается системное меню
  ([Web Share API](https://developer.mozilla.org/docs/Web/API/Navigator/share)) только с `url` и `title`, без готового текста;
  закрытие меню без выбора (`AbortError`) молчит. Иначе ссылка копируется ([Clipboard API](https://developer.mozilla.org/docs/Web/API/Clipboard/writeText)),
  тост «Ссылка скопирована» (повтор заменяет прежний). Если буфер закрыт, появляется ошибка (`ToastService.echoError`: действие пользователя, а не уведомление, поэтому паузы занятия её не гасят) и результат `failed`: экран показывает ссылку в
  `app-share-link-field` (URL-поле только для чтения; когда оно появилось, фокус переходит в него, ссылка выделена, пояснение связано `aria-describedby`); `execCommand` не используется.
- **`app-public-deck-card`.** Каркас карточки каталога: данные `PublicDeckCard` (`shared/public-deck-card.ts`), «Добавили» и
  «Учат сейчас» показываются от 10 и округляются вниз до двух значащих цифр (`audienceCount`: `null` и 9 — скрыто, 10 → «10», 1234 → «1,2 тыс.»; каталог присылает `null` вместо чисел меньше 10).
  Скрытый автор, пустые медиа, малые счётчики и пустые тема или язык не рисуются. Короткая форма («1,2 тыс.») — для глаз, скринридер читает полную («1,2 тысячи»); тема и язык имеют невидимые «Тема:» и «Язык:»; уровень заголовка — вход `headingLevel` (2–4, по умолчанию 3); у каждого экземпляра свой id.

### Копия чужой колоды («Добавить к себе»)

Контракт: [`contracts/decks/forks.json`](../../contracts/decks/forks.json), тексты: [«Копии» и «Экраны»](../product/community-decks.md). Три общих элемента лежат
в `shared/` и показаны в `/styleguide` («Статусы и ход»); слова копии — одним файлом `shared/copy-text.ts`.

- **`app-copy-mark`** — метка строки «Моих колод»: знак `copy-branch` (скрыт от скринридера) и слово «Копия»; если владельцу есть что знать — одно состояние после неё
  («Копия: Готовим колоду…», «Копия: Не удалось подготовить колоду», «Копия: Источник больше недоступен»). Отвязанная копия пометки о закрытом источнике не получает.
  На экране уже 30 rem состояние переходит на свою строку (разделитель-точка не остаётся в начале строки). Не ссылка и не кнопка: строка списка и так ведёт в хаб. Копия, которая готовится, в списке не «учится»: учить можно только из хаба готовой копии.
- **`app-copy-origin`** — строка под названием хаба. Источник доступен: «Копия колоды «Название»», название — ссылка на `/d/{код}`. Недоступен: одно утверждённое предложение
  «Автор закрыл исходную колоду. Ваша копия остаётся с вами, но обновлений больше не будет.» После «Отвязать от автора» рядом штамп «Отвязана от автора».
- **`app-copy-status`** — блок вместо содержимого хаба, пока копия не готова. `preparing`: «Готовим колоду…», что будет в копии («В копии будет: 40 материалов · 12 упражнений.»,
  числа приходят с сервера) и «Страница обновится сама, когда колода будет готова.»; полосы прогресса нет: сервер сообщает только флаги `fork`, число выдумывать нельзя.
  `failed`: «Не удалось подготовить колоду», «Повторить» (занята — «Повторяем…», `aria-busy` и `aria-disabled`, не `disabled`) и слот `[copy-actions]` (в хабе — «Удалить колоду» удержанием).
  `stalled`: страница перестала проверять сама, кнопка «Проверить снова». `aria-busy` стоит только на занятых кнопках, не на блоке. Блок не живая область: смену состояния озвучивает один раз область `role=status` самой страницы
  («Готовим колоду…», «Не удалось подготовить колоду.», «Колода готова.», «Копия отвязана от автора.»), поэтому скринридер слышит её единожды. Уровень заголовка — вход `headingLevel` (2 в хабе, 3–4 внутри страницы с более глубокой структурой, как у `app-access-screen`).
- **Хаб копии** (`own-deck-detail-page`). Пока `fork.preparing` (в том числе `failed`), страница не рисует «Учить», «Добавить материал», «На потом», «Изменить», блок доступа, Мастерские,
  статистику и материалы: всё это отвечает 409 `DECK_PREPARING`. Когда нажатая кнопка («Повторить», «Проверить снова») исчезла вместе со своим состоянием, фокус встаёт на заголовок блока; у только что открытой копии (фокус нигде) — на `h1`; ответ `fork:retry` показывается сразу (`applyFork`) и объявляется «Повторяем подготовку.». Страница читает колоду снова с ограниченной задержкой 1,5 → 2 → 3 → 5 → 8 с, затем каждые 10 с (`fork-poll.ts`), не больше 150 раз
  (около 25 минут), в скрытой вкладке не спрашивает, а когда вкладка снова видна (`visibilitychange`), смотрит сразу, но не чаще первого шага; когда `preparing` стало ложью, опрос останавливается, статистика читается заново, фокус, потерянный вместе с блоком, встаёт на заголовок.
  «Отвязать от автора» — пункт меню «⋯»; кнопка подтверждения описана абзацем о последствиях (`aria-describedby`); вопрос задаётся на месте, в странице (`section.notice.warning`, заголовок «Отвязать от автора?» получает фокус, Esc и «Отмена» возвращают фокус на «⋯»),
  без `confirm()` и модального окна: это не удаление, поэтому не «удержание».
- **Просмотр чужой колоды.** Вошедшему читателю в основном слоте: «Добавить к себе» (занята — «Добавляем…»; успех ведёт в хаб копии) или, если копия уже есть (`myCopy`), «Открыть мою копию».
  Повтор после потери ответа отправляет ту же команду (`commandId` живёт, пока исход неизвестен), после отказа — новую. Отказы — простые предложения под кнопкой (`role=alert`), экран не уходит.
  Токен ссылки `?invite=` убирается из адреса сразу при загрузке (`replaceUrl`), у гостя тоже; в адресе, истории, `returnUrl` входа и в транзакции OAuth (PKCE) его нет.
  Вошедший читатель погашает его сразу; токен лежит только в памяти компонента до ответа (повтор после 429 использует его). Гость: токен ждёт входа в одной записи
  `sessionStorage` этой вкладки `mnema.invite.pending` = `{token, code, createdAt}` не дольше 10 минут (`features/public-deck/invite-token-store.ts`, любой доступ к хранилищу в `try/catch`;
  без хранилища гость просто откроет ссылку ещё раз); `returnUrl` остаётся `/d/{код}`. После входа страница забирает запись один раз: удаляет её до запроса погашения; просроченная,
  повреждённая или чужая по коду запись не используется (просроченная и повреждённая удаляются). Если «Начать заново» в Study невозможна (409 `DECK_PREPARING`), экран предлагает ссылку «К колоде». Токен не попадает в логи, заголовок страницы и `localStorage`.
  Приглашённому гостю экран приглашения добавляет строку «Войдите, чтобы принять приглашение.» рядом с утверждённым предложением (при `?invite=` или при записи в хранилище; запись при этом не гасится), а пока токен гасится, страница пишет «Принимаем приглашение…» вместо «Загружаем колоду…». Сбои запроса доступа (422, 429, сеть, отмена) — `.notice.error` с `role=alert`; «Запрос отменён.» — `role=status`, и фокус встаёт на вернувшуюся «Запросить доступ».
  «Запросить доступ»: 403 `DECK_INVITE_ONLY` или 403 без тела (автор выключил запросы) отвечает тем же утверждённым предложением; любой другой 403 (например, `ACCESS_DENIED`) — обычное сообщение об ошибке.

### Обновление копии (экран обзора, Updates/5)

Контракт: [«Обновления»](../product/community-decks.md), RFC [§ 7.5](../reviews/community-decks-2026-10/rfc.md). Это каталог элементов экрана обзора; сам экран и его API делает следующая фаза.
Все элементы показаны в `/styleguide` (раздел «Обновление копии»), слова — в `UPDATE_TEXT` файла `shared/copy-text.ts`. Изменение всегда названо словом: цвет, подчёркивание и зачёркивание его только поддерживают.

- **`app-segmented-choice`** (общий): живая область (`aria-live="polite"`) есть с первого показа, но пуста; до первого изменения читателем пояснение выбранного варианта лежит в обычном абзаце (виден и описывает группу), после него текст появляется в той же живой области. Страница с десятками групп (строки списка) ничего не зачитывает при появлении, а первое изменение объявляется надёжно.
- **`app-update-badge`** — «Есть обновление» на карточке копии и в хабе: `.stamp.solid` с ромбиком (`aria-hidden`), слова первыми, не просто точка. Не живая область: список карточек не объявляет каждый значок.
  Закрытый источник — `app-unavailable-note subject="source"` («Источник больше недоступен» и утверждённое предложение).
- **`app-update-summary`** — `counts` (`materials`, `exercises`, `fixes`, `conflicts`, `deleted`), `note` («Что нового», до 500 символов), `busy`, `pendingNote` (выбор у конфликтов и удалений ждёт «Применить выбранное»: вторая строка под кнопкой), `headingLevel` (2 или 3), выход `acceptSafe`. Одна строка со склонением
  («+12 материалов, +30 упражнений, 5 исправлений, 2 конфликта, 3 удалено автором», пустые части не пишутся; `summaryLine`), главное действие «Принять всё безопасное», описанное строкой
  «Берём новое и исправления того, что вы не меняли. Ваши правки и удаления не трогаем.» (`aria-describedby`). Занята — `aria-busy` и `aria-disabled`, фокус сохраняется; когда безопасного нет (нет нового и исправлений) — `aria-disabled` и строка «Безопасного для приёма сейчас нет.»
  Блок не живая область: результат озвучивает `role=status` страницы.
- **`app-count-tabs`** — вкладки с числом («Конфликты: 2»). До этого в продукте вкладок не было, это единственная реализация: шаблон [APG tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) с автоматическим выбором
  (стрелки, Home, End; в Tab-порядке только выбранная вкладка). Вход `tabs` (`value`, `label`, `count`), `label` (имя списка вкладок), `[(value)]`. Панель рисует страница: `role="tabpanel"`, `[id]="tabs.panelId(value)"`,
  `[attr.aria-labelledby]="tabs.tabId(value)"`. Выбранная вкладка — толстая линия и жирный текст, в `forced-colors` линия берёт `Highlight`.
- **`app-compare-columns`** — «Сейчас у вас» | «Вариант автора»: две группы (`role="group"` с заголовком уровня `headingLevel` 3–5) в порядке «моя, авторская»; содержимое — слоты `[compare-mine]` и `[compare-author]`.
  Нет вашей стороны (`mineAbsent`) — «Нет у вас», автор удалил (`authorAbsent`) — «Автор удалил», каждое с одним простым предложением. Раскладка по ширине **контейнера** (`container-type: inline-size` и `@container`), не окна:
  уже 44 rem — одна сторона и переключатель `app-segmented-choice` («Какую версию показать», живое «Показана ваша версия.»), от 44 rem — колонки рядом, переключатель `display: none` (нет в порядке фокуса). Движения нет, поэтому reduced motion ничего не требует.
  Пока страница не задала `side`, единица без вашей стороны открывается на варианте автора, без авторской на вашей. Известный край: если контейнер стал шире 44 rem, пока фокус на переключателе, переключатель исчезает и фокус уходит на страницу; принято, не обрабатывается.
  Заголовки колонок на уровне `headingLevel`; `app-compared-document` внутри берёт его у колонок и рисует свои заголовки с уровня ниже (уровень 1 документа на H + 1, смещение H − 1; явный `headingOffset` главнее), так что структура не прыгает и не повторяет уровень.
- **`app-compared-document`** — одна сторона сравнения материала: тот же `app-native-document-renderer`, что в Browse. Блок на другой стороне находится по стабильному id узла (`compareDocuments`, `shared/document-changes.ts`);
  изменённые блоки помечены через `BlockOverlay.marked` и подписаны штампом («Изменено», «Добавлено», «Удалено автором»); у абзаца, чьи слова изменились, блок заменён списком слов (`hidden` и `before`, как в Мастерской).
  Id узлов попадают в DOM (`exposeNodeIds`), файлы приходят через `assetSources`, как у renderer, а при `mediaAudience` (`owner` или `public`) документ рисует `app-native-media-surface`, которая сама берёт файлы у предоставленного `MediaPlaybackApi` (экран обновления: своя сторона читает по маршруту владельца, сторона автора по публичному маршруту источника). Название строки `app-update-unit-row` переносится и целиком доступно; обрезка до двух строк только в закрытой строке шире 40 rem.
- **`app-word-diff`** — слова изменений по `content/word-diff.ts` (перенесён из `features/generation`, им же пользуется Мастерская): `<del>` зачёркнуто, `<ins>` подчёркнуто, перед каждым скрытое «удалено:» или «добавлено:»;
  `side` = `mine` (слова автора скрыты), `author` (удалённое скрыто) или `both`. В `forced-colors` линии остаются, добавленное берёт `LinkText`.
- **`app-update-unit-row`** — строка единицы плана (`unit`: `kind`, `title`, `class`, `dependency`). Вид — знак `app-glyph` и слово (материал, упражнение, цель, описание колоды, порядок материалов), класс — штамп словами
  («Новое», «Исправление», «Конфликт», «Удалено автором», «Снова изменено»; конфликт `.solid`). Решение — `app-segmented-choice`, не флажок: у каждого класса два ответа с глаголами
  («Принять» / «Не брать», «Оставить моё» (по умолчанию; так же у «Снова изменено») / «Взять вариант автора», «Оставить у себя» (по умолчанию) / «Удалить и у меня»; это `choicesPerClass` контракта), а один флажок прятал бы второй ответ за «не отмечено». Легенда называет единицу и
  не рисуется (`legendHidden`), кроме удаления, где она видимый вопрос «Удалить «…» и у меня?». Модель `choice` равна `null`, пока читатель не выбрал: новое и исправление тогда «не решено», конфликт, «Снова изменено» и удаление стоят на ответе по умолчанию.
  Кнопка «Сравнить» / «Свернуть сравнение» с `aria-expanded`, `aria-controls` (пока открыто) и именем «Сравнить: «Название»»; тело строки — слот: страница кладёт туда `app-compare-columns`. Проецируемое содержимое создаётся и у закрытой строки,
  поэтому тяжёлое оборачивают в `@if (row.expanded())` через ссылку на строку. Зависимость: «Нужен материал «…». Он будет добавлен вместе с этим.» Заданное страницей решение (`locked`) остаётся в порядке фокуса, но не меняется; `lockNote` рисует прямо под выбором штамп «Обязательно» со знаком замка и причину словами, причина входит в `aria-describedby` группы, так что закрытая строка не держится на цвете или `aria-busy`.
- **`app-update-news`** («Что нового», Updates/6 часть B) — компактный блок хаба копии после автоматического приёма, под рядом действий (так «Учить» остаётся на первом экране телефона): маленький `h2` «Что нового», время обновления в `<time>`
  («2 часа назад, 12.10.2026, 12:30», `appliedAt` и `when`) и одно предложение со склонением («Автор обновил колоду, мы взяли 3 изменения автоматически. 2 ждут вашего решения.»; без «ждут», если решать нечего; `applied` = 0 даёт «Автор обновил колоду.»).
  Без рамки-листа и без своей кнопки: действия (ссылки) кладёт страница. Страница показывает блок, только пока `fork.lastUpdate` есть у готовой привязанной копии и запись не отмечена просмотренной в этой вкладке (`UpdateSeenState`).
  «Посмотреть, что изменилось» — текстовая ссылка в историю (история сама отмечает записи просмотренными); «Решить, что взять» нужна, только если решения ждут, а блока «Есть обновление» нет. Если у автора есть и новое обновление, блок один (`offer`):
  в нём значок «Есть обновление» и единственная кнопка «Посмотреть обновление», отдельный блок предложения рядом не рисуется. Не живая область: обновление пришло, пока владельца не было.
- **`app-update-history-unit`** — единица в истории обновлений (`unit`: `kind`, `change`, `title`, `state`); страница кладёт её в пункт списка `li` (`tabindex="-1"`: после возврата фокус встаёт на него, и он читается как «Вы уже вернули»), вложенного `article` нет.
  Вид — знак и слово, что с единицей сделало обновление — штамп словами («Добавлено», «Исправлено», `.solid` «Удалено»), название целиком (переносится), для единицы, которая уже не такая, как после обновления, — предложение «Вы уже вернули» или «Вы изменили после обновления».
  Порядок материалов не повторяет штамп и название: одна строка со знаком «Изменился порядок материалов». Действие строки — слот: страница кладёт «Вернуть как было» (кнопка `.button.small`, имя «Вернуть как было: «Название»»; у одноимённых единиц разных обновлений имя добавляет «, обновление от дата, время»;
  только у материала и упражнения, оставшихся ровно такими, как сделало обновление) и, после нажатия, подтверждение на месте кнопки: `.notice.warning` с `role="group"` и `tabindex="-1"`, имя группы — вопрос в одно предложение («Уберём «…» из вашей колоды.», «Вернём «…» к тому, что было до обновления.», «Вернём «…» в вашу колоду на прежнее место.»),
  описание (`aria-describedby`) — все остальные абзацы: подсказка «Следующее обновление не вернёт это обратно, пока автор не изменит его снова.» и, на втором шаге после 400 `unit_needed`, по строке на вид изменения («Вместе с этим уберём: …», «вернём: …», «вернём к прежнему виду: …») и «Они связаны между собой, поэтому возвращаются вместе.».
  Фокус уходит на группу (она читается целиком), Escape и «Отмена» возвращают его на кнопку. Если вопрос закрыт ответом сервера (изменено после обновления, отвязана, готовится, не найдено), фокус и прокрутка идут на заметку над списком, одну за раз. Страница истории (`/decks/:deckId/update/history`) собирает записи в `ol`:
  у каждой `h2` «Автоматически, 3 часа назад» (способ и `<time>`), точное время ниже, когда в заголовке фраза, и счётчики. Успех — только тост; фокус встаёт на вернувшуюся единицу.

Геометрию (рядом или одна сторона) проверяет браузерная проверка следующей фазы; в jsdom её нет.

### Сообщество (Community/4 to 6, фаза A)

Элементы страницы «Сообщество», поиска и страницы автора собраны в `/styleguide` раньше самих страниц (раздел «Сообщество», `sg-community`, фикстуры в
`sg-community-demo.ts`). Они не ходят в сеть: данные, адрес и действия приходят от страницы, которая подключается к API в фазе B. Тексты берутся из
[«Сообщество», «Поиск», «Профиль автора» и «Экраны»](../product/community-decks.md) и [RFC §13](../reviews/community-decks-2026-10/rfc.md#13-интерфейс).

- **`app-book-search`.** `<search aria-label="Поиск колод">` (единственная область поиска) › обычная `<form>` (без role и имени) › видимая подпись «Найти колоду» › `<input type="search" name="q" maxlength="100">` › кнопка «Найти»
  со знаком `book-search`. Enter и кнопка запускают поиск, пустой запрос разрешён и значит «показать всё»; `(searched)` отдаёт обрезанный текст, `value` и `expanded`
  это `model()`. `mode="open"` (страница): книга лежит раскрытой, поле видно, раскрытие (`.5s`, `clip-path` от корешка, `backwards`, то есть без следа после конца,
  чтобы не обрезать контур фокуса) проигрывается один раз за загрузку страницы (решается при создании, в `ngOnInit`: первая раскрытая книга; закрытая кнопка шапки его не тратит) и отключено при
  `prefers-reduced-motion` (контракт закреплён в `book-search.css.spec.ts`). `mode="closed"` (шапка): кнопка «Открыть поиск колод» (имя отличается от имени области) с `aria-expanded` и `aria-controls`, нажатие
  раскрывает ту же форму и переносит фокус в поле, Esc складывает книгу, возвращает фокус на кнопку, не стирает текст и не уходит выше (`stopPropagation`), пустое поле складывается, когда фокус уходит из поиска.
  Подключение к шапке и маршрут сделаны в фазе B (раздел «Страница «Сообщество»» ниже). Подсказка `app-typewriter-hint` лежит поверх поля (`aria-hidden`, `pointer-events: none`), атрибут `placeholder` не используется.
- **`app-typewriter-hint`.** Печатает идею из пула по буквам (75 мс), держит (1,8 с), стирает (35 мс) и берёт следующую в порядке `seed` (по умолчанию один на загрузку страницы). Не зацикливается (WCAG 2.2.2): один проход по не более чем трём идеям, последняя остаётся напечатанной и неподвижной (и после фокуса и ухода из поля).
  Останавливается и скрывается, когда в поле фокус или текст (`suppressed`) и когда вкладка скрыта (`visibilitychange`); при уменьшенном движении (или `still`) показывает одну
  статичную идею и не заводит таймеров; в `forced-colors` идея `GrayText`. Все таймеры живут в одном `effect` и снимаются при завершении; `NgZone` не нужен. Пул из 50 идей `SEARCH_IDEAS` повторяет RFC слово в слово и в том же порядке.
- **`app-catalog-filters`.** Чистое «значение внутрь, значение наружу»: `value: CatalogFilters`, `(changed)`. Модель и помощники лежат в `shared/catalog-filters.ts`:
  `toQueryParams` и `fromQueryParams` (строго: неизвестное отбрасывается, повторяющиеся `media` и `mechanics` собираются без дублей в порядке списка, у одиночных берётся первое,
  порядок ключей фиксирован, сортировка по умолчанию «Популярные» без текста в адрес не пишется; с текстом `q` сортировка «По близости к запросу» (`relevance`) это отсутствие `sort`, она не пишется никогда, а любая другая, «Популярные» тоже, пишется, потому что отсутствие значило бы близость; `toQueryParams(filters, searching)`, `fromQueryParams` читает `sort` вместе с `q`), `activeCount` (сортировка не считается), `withoutFilter`, `withoutFilters`. Темы и языки приходят входами
  `topics` и `languages`. Тема это `app-mnema-select` с группами по `parentName`, «Что учим» и «Уровень» тоже `app-mnema-select` с «Любой», «Размер» и сортировка это
  `app-segmented-choice` (у размера подсказка выбранного: «Меньше 50», «От 50 до 300», «Больше 300 материалов»), «Внутри», «Упражнения» и «Живая» это `.check-row`. Узкий контейнер
  (меньше 46 rem, `@container`): всё за кнопкой «Фильтры» (`aria-expanded`, `aria-controls`, «Фильтры · 3»); широкий: сетка в ряд, кнопки нет. Сортировка видна всегда. Каждый включённый фильтр это чип-кнопка (`.button.small`), которая называет и категорию («Тема: …», «Что учим: …», «Уровень: B1», «Размер: на месяц», «Внутри: аудио», «Упражнения: на слух», «Живая»); имя «Убрать фильтр «Уровень: B1»» содержит видимый текст, рядом «Сбросить всё» (сортировка остаётся). После удаления чипа фокус идёт на чип, занявший его место (у последнего на предыдущий), а когда чипов нет, на кнопку «Фильтры»;
  если страница применила значение позже, фокус ставится в момент, когда удалённый чип действительно исчез; заявка гаснет, если читатель успел перейти на другой элемент вне чипов, и через 2 с. «Для вас» (эпик 4) принимается из адреса как private `CatalogSort` и добавляется отдельной опцией при входе `forYou=true`; публичный wire-список `CATALOG_SORTS` остаётся прежним. Без серверного разрешения и входа страница нормализует такой адрес к популярным.
  Вход `searching` (есть текст поиска) ставит первым вариантом сортировки «По близости к запросу»; без текста его нет в списке. Сортировка с текстом включена всегда, строки о недоступности нет; выбор другой сортировки оставляет `q` в адресе и уходит в запрос (`sort` вместе с `q`), «По близости» это запрос без `sort`.
- **`app-deck-shelf`.** `section` без имени (область на каждую полку была бы шумом; ориентир это `h2`) с `h2`, строкой под ним, ссылкой «Все» (имя «Все колоды: …») и `ul[role=list]` из `app-public-deck-card` (заголовки `h3`). Широкий контейнер: сетка; узкий:
  ряд с прокруткой в сторону и `scroll-snap`, карточка 82 % ширины, следующая выглядывает из-за края, без затухания поверх текста. Список не фокусируется: остановки это ссылки и кнопки карточек.
  **Правило страницы:** полка меньше чем из 4 колод не рисуется, на полку попадает не больше одного ряда (4 до 6 карточек), остальное за «Все».
  Вход `moreQueryParams` задаёт запрос ссылки «Все» (страница держит состояние в адресе: `/community?sort=learning`). Вход `menuFor` выдаёт пункты меню «⋯» для каждой колоды, когда они различаются
  (нет «Пожаловаться» на свою колоду); без него у всех `menuItems`. Тот же `menuFor` есть у `app-deck-grid`.
- **`app-deck-grid`.** Сетка `ul[role=list]` карточек с общей `app-auto-load` (кнопок страниц и «Показать ещё» нет; вход `context` и `root` передаются как у списка выше). Карточка, новая для сетки,
  появляется чернильным открытием `mn-ink-in` (`.5s`, `backwards`) с каскадом по 40 мс, не более восьми карточек порции; карточки, уже стоящие в списке, не анимируются при добавлении страницы;
  при уменьшенном движении нет ни открытия, ни каскада (`deck-grid.css.spec.ts`). Число результатов звучит вежливо один раз на поиск (`role=status` без лишнего `aria-live`; область всегда в разметке, пока пуста сворачивается до нулевой высоты, а не `display: none`; текст кладётся в неё после первого рендера, так что сетка, созданная уже с результатами, тоже объявляет; строка видна):
  «Нашли 37 колод», «Нашли больше 200 колод» (сервер ограничил счёт), «Ничего не нашли. Попробуйте другое слово или уберите фильтры.» (склонение через `plural`). Страница передаёт
  `results = { key, count, capped }` после первой порции поиска и `null`, пока она грузится или читатель просто листает; новый `key` это новое объявление, подгруженные страницы молчат.
- **`app-community-empty`.** `.empty-state` с утверждённым текстом «Пока здесь пусто. Сделайте свою колоду публичной, и она появится здесь первой.» и раскрывающимся (`details`)
  «Как поделиться колодой»: три шага (открыть колоду, в «Доступ и публикация» выбрать «Публичная», пройти чек-лист) и порог каталога обычными словами: «В колоде должно быть не меньше 10 материалов, хотя бы одно упражнение и описание.» (шаги и порог наши, одобренные два предложения выше не менялись). Вошедшему ведёт «Мои колоды» (`/decks`), гостю «Войти» (`/login`).
- **`app-author-header`.** Фото 64 px (без него кружок с буквой, как у чипа автора), `h1` (имя, иначе `@логин`; вход `headingLevel` опускает уровень там, где шапка не заголовок страницы),
  строка `@логин` при имени, описание простым текстом (`white-space: pre-line`, без HTML и автоссылок), «Учат сейчас: N» от 10 с округлением (`audienceCount`), меню «⋯» с «Поделиться»
  (адрес профиля, как у карточки) и «Пожаловаться» (выход `complain`; окно жалобы `app-complaint-dialog` с `target="profile"` открывает страница). Для себя (`isSelf`): жалобы в меню нет,
  заметка «Так ваш профиль видят другие» и ссылка «Настроить профиль» (`/profile`).
- **Карточка.** `app-public-deck-card` получила вход `note`: штамп рядом с темой и языком (например, «Доступна вам» у колоды по приглашению в профиле). Вход `authorShown` (по умолчанию включён) убирает чип автора там, где все колоды списка одного автора
  (страница профиля): чип повторял бы одно и то же на каждой карточке. У `app-deck-grid` те же две возможности: `authorShown` для всех карточек и `noteFor` (функция, как `menuFor`: пометка отдельной карточки или `null`).

Доступность: все элементы проходят клавиатурой (Tab, Enter, Пробел, Esc), видимый фокус, имя и состояние у каждого элемента управления, живые области вежливые и не болтливые, уменьшенное движение,
200 % и 320 px без горизонтальной прокрутки страницы, `forced-colors` не теряет состояние (кнопки, чипы и штампы с рамкой, смысл в словах). Геометрию (`@container`, `scroll-snap`, раскрытие книги) jsdom не проверяет:
для этого нужен настоящий браузер.

### Страница «Сообщество» (Community/4 и 5, фаза B)

`/community` (`features/community`, гости тоже, без `authGuard`) соединяет элементы выше с публичным API каталога ([`contracts/community/catalog.json`](../../contracts/community/README.md);
строгие разборщики `community.models.ts`, исполняемый пример `community-contract.spec.ts`). **Адрес это состояние страницы:** `q` и параметры фильтров `catalog-filters.ts`; поиск из книги
добавляет запись в историю, фильтр заменяет её (`replaceUrl`), сортировка ждёт 300 мс последней стрелки, и запрос уходит один. Пока в адресе нет ни текста, ни фильтра, ни сортировки, это полки
(«Выбор Мнемы», «Учат сейчас», «Новое», темы; один ряд, до 6 карточек и «Все» на `/community` с запросом полки, а у полки без «Все» (выбор Мнемы) все карточки, до 12); иначе выдача `app-deck-grid` с автоподгрузкой (дубли по коду отбрасываются,
412 тихо начинает список с первой страницы, сбой следующей порции ждёт «Повторить» автоподгрузки, прежний запрос отменяется). Число результатов объявляется один раз на новый запрос или фильтры; «больше N» звучит только когда сервер сказал `totalCapped`.
Если колод в каталоге нет (`listedCount` 0), страница показывает `app-community-empty` без фильтров и полок, книга остаётся. Если колоды есть, но ни одна полка не набрала четырёх, вместо
пустой страницы идёт список от новых к старым (`sort=new`; пока колод так мало, популярности ещё нет), и переключатель сортировки показывает «Новые». С текстом поиска первая сортировка «По близости к запросу», без `sort` в адресе; страница разрешает другие сортировки, `q` при этом остаётся. Адрес из старой или чужой ссылки: тема и язык, которых нет в фасетах, убираются из адреса (`replaceUrl`) с одним вежливым замечанием (`role=status`, в разметке всегда): «Фильтр «Немецкий» больше недоступен, показываем без него.», если у убранного значения есть имя (так бывает у языка), иначе «Один из фильтров больше недоступен, показываем без него.» (значение из адреса не показывается; следующий поиск или смена фильтра убирает замечание), а значение, которое сервер не знает (400), даёт пустую выдачу «Ничего не нашли…» с чипами, чтобы фильтры можно было снять. Отказы: 404 (каталог выключен) это спокойное «Раздел «Сообщество» скоро откроется.» со ссылкой и кнопкой «Проверить ещё раз», 429 и 503 это замечание со словами страницы колоды и «Повторить». Нажатая кнопка уходит вместе с замечанием, поэтому после «Повторить» и после окна жалобы, закрытого ответом «колода недоступна», фокус идёт на `h1` страницы (у него видимый контур при фокусе с клавиатуры).
Автор приходит из Identity пачками по 50 только для показанных карточек и карточки не задерживает (скрытый профиль и сбой пачки это карточки без имени; сбойная пачка спрашивается снова при следующей смене показанного). «Пожаловаться» есть у любой колоды, кроме своей; гость идёт на вход и возвращается на тот же поиск.

**Запуск за флагом.** `COMMUNITY_LAUNCHED` (`shared/community-launch.ts`, токен `COMMUNITY_LAUNCH` для тестов) выключен, пока владелец не откроет каталог после сквозной проверки; PR запуска меняет его
вместе с `learning.community.catalog.enabled`. Включённым он добавляет пункт «Сообщество» в шапку (вошедшему вторым: «Мои колоды · Сообщество · Новая колода · Профиль», гостю первым), закрытую книгу-вход справа
перед блоком входа (на странице «Сообщество» её нет: у страницы один ландмарк поиска) и ссылку «Посмотреть колоды сообщества» в пустых «Мои колоды», когда в каталоге есть колоды (один запрос фасетов).
Маршрут `/community` существует всегда. Так же всегда существует `/u/:username` (раздел ниже); флаг прячет только входы: ссылку «Открыть публичную страницу профиля» (под заголовком «Как меня видят другие») в блоке «Публичный профиль» настроек профиля (`/profile`;
показывается, когда согласие включено и есть логин).

### Страница автора `/u/:username` (Community/6, фаза C)

`/u/:username` (`features/community/author-page.component.*`, гости тоже, без `authGuard`, доступна и при выключенном `COMMUNITY_LAUNCHED`) соединяет `app-author-header` и `app-deck-grid`.
Карточку автора страница сначала берёт у Identity (`AuthorCardsService.byUsername`): неизвестный логин, профиль без согласия и отозванный это одно и то же `null`, и страница говорит
`app-access-screen` «Профиль не найден» («Такого профиля нет, или автор его скрыл.», ссылка «В Сообщество» на `/community`), заголовок вкладки «Профиль не найден — Mnema», колоды при этом не запрашиваются
(Learning согласия автора не знает). Сбой самого запроса к Identity это «Не удалось открыть профиль» с «Повторить». Заголовок `h1` получает фокус, как на других страницах, когда профиль появился (шапка
имеет `tabindex="-1"` у `h1`); вкладка называется «@логин — Mnema» или «Имя (@логин) — Mnema».

Шапка: фото через `AuthorCardsService.avatarUrl`, имя, `@логин`, «О себе», «Учат сейчас» (сумма из ответа колод, от 10); «Поделиться» отдаёт `https://<origin>/u/<логин>`, «Пожаловаться» вошедшему чужому
зрителю открывает `app-complaint-dialog` с `target="profile"`, гостя отправляет на вход и обратно на эту страницу; 404 жалобы заставляет страницу прочитать карточку заново (кэш карточек живёт минуту,
`AuthorCardsService`). Для себя (`isSelf`, `accountId` вошедшего равен `accountId` карточки) нет жалобы и есть заметка со ссылкой «Настроить профиль». Если вошедший открыл свой логин (`profileUsername` аккаунта совпадает с адресом без учёта регистра), а Identity карточки не отдаёт (согласие выключено), вместо «Профиль не найден» страница говорит «Ваш профиль скрыт от других. Включите публичный профиль в настройках.» (`app-access-screen`, ссылка «Настройки профиля» на `/profile`, вкладка «Профиль скрыт»); для чужого логина и для гостя текст прежний.

«Колоды автора» (`h2`): `CommunityApiService.authorDecks` (`GET /api/public/community/authors/{accountId}/decks`) и общий `CommunityPager` (дубли по коду отбрасываются, 412 тихо начинает список заново, сбой
следующей порции ждёт «Повторить» автоподгрузки), сетка `app-deck-grid` без объявления числа (`results=null`), без чипа автора (`authorShown=false`), карточки с заголовками `h3`. Публичная колода ведёт на
`/d/{code}/{slug}`, колода «по приглашению» (`access: GRANTEE`: без slug, темы, счётчиков, медиа и механик) на `/d/{code}` с пометкой «Доступна вам». Разборщик строгий: у `GRANTEE` нет ничего из перечисленного,
у `PUBLIC` есть slug. В меню «⋯» своей колоды нет «Пожаловаться» (по `ownerId`). Колод нет: «У автора пока нет открытых колод.»; у самого автора «Здесь появятся ваши публичные колоды.» со ссылкой «Мои колоды».
Отказы как на странице «Сообщество»: 429 и 503 замечанием с «Повторить» (после него фокус идёт на заголовок «Колоды автора», `h2` с `tabindex="-1"`, так же после окна жалобы на колоду, закрытого ответом «колода недоступна»); 404 колод (каталог выключен) оставляет шапку и пишет «Колоды появятся здесь, когда откроется Сообщество.».

### Экран отказа и публичный просмотр колоды

- **`app-access-screen`.** Страница, которая объясняет, почему колоды не видно. Заголовок (`h1` по умолчанию, `headingLevel` 2–4 внутри страницы со своим `h1`;
  `tabindex="-1"`, чтобы оболочка и экран могли поставить на него фокус), одно короткое объяснение (содержимое по умолчанию) и действия, которые
  уже работают (слот `[access-actions]`: ссылка или кнопка). Мёртвых кнопок нет: «Запросить доступ» и «Отменить запрос» стоят на экране «по приглашению»
  у вошедшего читателя (Share/13), «Добавить к себе» — в основном слоте просмотра (Share/10). Линии сверху и снизу, как у `.empty-state`; тон передают слова.
- **Публичный просмотр `/d/:код/:slug` и `/d/:код`** (`features/public-deck/`, без `authGuard`, гостям тоже) собран из каталога: шапка из `.eyebrow`,
  заголовка, метки уровня (`.stamp` со знаком `app-glyph`: «Публичная», «По ссылке», «По приглашению»), `app-author-chip`, `app-share-button` и
  `app-action-menu` («Поделиться» и, для читателя, «Пожаловаться»; у владельца колоды только «Поделиться») с окном `app-complaint-dialog`, `app-segmented-choice` («Материалы» и «Упражнения», подсказка «Показаны упражнения: N» озвучивается при выборе), списки `app-auto-load`
  без кнопок страниц, материал в `app-native-media-surface` (`audience="public"`, без `data-node-id`), экраны отказа выше. Новых общих элементов, кроме
  `app-access-screen`, этот экран не вводит; заголовок хаба и строки списков живут в файлах страницы, как раскладка.
- **Адрес.** Slug есть только у PUBLIC-колоды; неверный или отсутствующий slug заменяется на канонический (`replaceUrl`), у LINK и INVITE slug не показывается.
  Материал открывается в той же странице как `?material=`, так что «Назад» возвращает к списку.
- **Голова страницы.** Пока маршрут активен, стоит `<meta name="referrer" content="no-referrer">`, а `robots: noindex` стоит, пока колода не загружена и
  не оказалась PUBLIC (LINK, INVITE и все экраны отказа не индексируются); при уходе `robots` возвращается к `index,follow` из `index.html`, а политика реферера сначала ставится в `strict-origin-when-cross-origin` (заголовок nginx, [browser security headers](../operations/browser-security-headers.md)) и только потом тег убирается: Chrome держит последнюю применённую политику. Внешние ссылки в материале
  имеют `rel="ugc nofollow noopener noreferrer"`. OG-карточка и серверный `X-Robots-Tag` — Share/14.
- **Список и материал.** Список материалов остаётся смонтированным (скрытым), пока открыт материал: «Назад» возвращает те же строки, курсор и место.
  На странице материала есть «Предыдущий» и «Следующий» (соседей список дочитывает сам, не больше 20 порций), заголовки документа лежат ниже `h2` материала
  (`headingOffset`: уровень 1 документа становится 3). После 412 список читается с начала, статус «Автор обновил колоду…» — постоянный `role=status`, голова списка
  прокручивается в видимую область. «Повторить» после 429 имеет `aria-disabled` до конца `Retry-After` (с обратным отсчётом в тексте).
  Материал, снятый по жалобе, остаётся строкой «Материал недоступен» (`app-unavailable-note`) без ссылки, «Предыдущий» и «Следующий» его пропускают, а прямой адрес (`410`) показывает спокойный «Материал недоступен»; упражнение — «Упражнение недоступно».
- **Клавиатура и скринридер.** Фокус после загрузки и смены экрана переходит на `h1` страницы, при открытии материала — на его заголовок «Материал N из M»
  (`tabindex=-1`), при возврате в хаб — на строку, которая была открыта (всё это, если читатель сам не увёл фокус); список —
  `ol` с одной ссылкой на строку (вся строка кликабельна растянутой ссылкой, фокус виден контуром), продолжение списка озвучивается через `role=status`,
  ошибка — одна кнопка «Повторить»; уровень доступа читается словом («Доступ: Публичная»), а не значком.

### Кабинет владельца: «Выбор Мнемы» и флаги накруток (`/manage/community`)

Раздел «Сообщество» кабинета (только admin-хост, пункт навигации рядом с «Жалобы»). Контракт: `editorial` и `anomalies` в [`contracts/community/catalog.json`](../../contracts/community/catalog.json).

- **`app-order-row`** (`shared/`, образец в «Выбор» `/styleguide`). Строка списка, порядок которого задаёт человек: позиция, проецируемое тело (название, код, штамп «Не в каталоге») и три нативные кнопки «Выше», «Ниже», «Убрать». Перетаскивания нет. У первой строки «Выше» и у последней «Ниже» остаются в порядке фокуса как `aria-disabled` и ничего не делают; пока идёт запрос, `aria-disabled` у всех трёх (`disabled` не используется, фокус не теряется). Имя кнопки начинается с видимого слова и называет строку («Выше: Столицы мира»). Ошибка строки это `.field-error`, на неё ссылаются три кнопки (`aria-describedby`). Список (`ol[role=list]` с `li`), фокус и объявления остаются на странице: после «Выше» и «Ниже» фокус возвращается на ту же кнопку на новом месте, после «Убрать» идёт на «Убрать» соседней строки (если строк нет, на поле «Добавить колоду»), а новое место называет вежливая область `role=status` («Столицы мира: место 2 из 5.»).
- **«Выбор Мнемы».** Не больше 24 колод; подпись раздела называет правила показа: «До 24 колод. Сообщество показывает первые 12, а полка видна, когда в каталоге не меньше 4 из них.» (числа из `SHELF_DECKS_MAX` и `SHELF_MIN_DECKS`). «Добавить колоду» принимает публичную ссылку `https://…/d/{код}[/{слаг}]` или код из 10 знаков base58; алфавит и длина проверяются на месте, существование и публичность решает сервер. Заполненный список делает «Добавить» `aria-disabled` с подсказкой «На полке уже 24 колоды…». Список меняется на месте и уходит целиком кнопкой «Сохранить» (свежий `commandId`, `If-Match` = `rowVersion`; неизвестный исход повторяет ту же команду). Исходы словами: «Сохранено» (вежливая область; затем список перечитывается, у новых колод появляются названия), `412` «Список изменился, вот актуальный. Повторите изменения.» (актуальный список заменяет правки), `400` помечает названные сервером колоды ошибкой строки и переносит фокус на первую «Убрать». Колода без листинга остаётся строкой со штампом «Не в каталоге». Несохранённый список защищён `canDeactivate` и `beforeunload` (как редакторы промокодов и пользователей).
- **«Флаги накруток».** Общий `CursorList` и `app-auto-load` (курсор `next`, без кнопок страниц): название-ссылка на `/d/{код}` публичного хоста в новой вкладке, «Копий за 7 дней: 42», «Новых аккаунтов: 83 %», дата выявления, состояние словами («Открыт» или «Просмотрен 6 октября…»; цвет его не несёт). У открытого флага кнопка «Просмотрено» (свой `commandId`, повтор безопасен); после неё строка показывает состояние «Просмотрен», кнопка исчезает, фокус остаётся на заголовке строки (`h3` с `tabindex=-1`), а вежливая область раздела объявляет «Флаг «…» отмечен просмотренным.». Отказ пишется в строке (`.field-error` с `id`, на него ссылается `aria-describedby` кнопки). Пусто: «Флагов нет.»; пустой `ul` не рисуется.
- **Области состояния.** В каждом разделе одна `role=status`, она в разметке всегда и пуста, пока нечего сказать (текст кладётся в неё, область не появляется вместе с текстом): «Загружаем полку…», «Сохранено», новое место строки, «Нечего сохранять» (нажатие «Сохранить» на неизменённом списке), «Идёт сохранение, подождите». Ошибка поля «Добавить колоду» (`role=alert`) говорит и о полной полке: «На полке уже 24 колод. Уберите одну, чтобы добавить другую.».
- **Уход со страницы.** Пока список сохраняется, уход запрещён: область говорит «Идёт сохранение, подождите», фокус идёт на «Сохранить». С несохранёнными правками на странице появляется замечание о них и спрашивает `window.confirm` (как у других редакторов).

### Жалобы, скрытие и снятие (Share/15)

Контракт: [`contracts/moderation`](../../contracts/moderation/README.md). Новые общие элементы показаны в `/styleguide` («Меню и окна», «Статусы и ход»).

- **`app-complaint-dialog`** (`shared/`). «Пожаловаться» на публичную колоду (пункт «⋯» чужой колоды; у владельца пункта нет) и, позже, на профиль
  (`ComplaintApiService.fileProfile`, экрана пока нет). Модальный `<dialog>` по образцу промо-окна: платформа держит фокус внутри и делает остальную страницу
  недоступной; при открытии фокус на заголовке. Любой выход (Esc, «×», «Отмена», успех, 404) закрывает нативное окно, пока оно ещё в документе, возвращает фокус на «⋯» и только потом сообщает странице; без этого убранное из дерева окно оставляло фокус на `body`. Ошибка «Выберите причину.» связана с группой (`aria-describedby`, `aria-invalid`); при конце сессии в ошибке есть ссылка «Войти» с возвратом на эту страницу. Содержимое: заголовок, название колоды, «Мы рассмотрим жалобу в течение
  30 дней. О решении мы не пишем.», причина (`app-segmented-choice`, нативная группа переключателей: «Нарушены авторские права», «Раскрыты личные данные», «Запрещённое
  содержимое», «Спам или реклама», «Другое»; под группой живая подсказка к выбранной), необязательный текст до 1000 знаков со счётчиком «N из 1000» (считаются символы, не
  кодовые единицы UTF-16; перегрузку называет `field-error`), «Отправить жалобу» и «Отмена». Без причины отправка не уходит: звучит «Выберите причину.», фокус на группе.
  Пока жалоба уходит, кнопки и переключатели `aria-disabled` (группа не `disabled`, фокус не теряется), Esc и «×» ждут ответа; если платформа всё же закрыла окно (второй Esc), оно открывается снова. Исходы словами: успех закрывает окно и даёт простой тост «Жалоба отправлена» (сначала окно закрывается, потом тост, иначе его держит модальность); 404 закрывает окно и даёт
  тост-ошибку «Колода больше недоступна» (страница заново спрашивает сводку); 429 оставляет окно с текстом и пишет «Попробуйте позже»; конец сессии, отказ и неизвестный исход
  называются в окне, повтор безопасен (жалоба идемпотентна). Гость окна не видит: пункт ведёт на вход с возвратом на ту же страницу.
- **`app-unavailable-note`** (`shared/`). Тело строки списка, чей материал или упражнение сняты по жалобе: «Материал недоступен» / «Упражнение недоступно» и одна строка
  причины словами. Строка остаётся на месте и с номером. Читателю публичной колоды действий нет; автору внутрь кладутся «Заменить» (ссылка в редактор с чистой страницей на
  том же месте: `?ordinal=` и `?replace=<версия из списка>`) и «Удалить…» (выбирает строку и переносит фокус на кнопку «Удалить выбранные» панели с удержанием; пока считается превью, кнопка панели остаётся в порядке фокуса с `aria-disabled`: у `app-hold-to-delete-button` для этого вход `focusable`), у упражнения только «Удалить упражнение N».
  Кнопки строки начинаются с видимого слова и называют номер («Заменить материал 4»). Звезда «Эталон», счётчик упражнений и ссылка на материал у такой строки не рисуются.
  Открытие снятого материала (`410`) показывает спокойный экран «Материал недоступен», а не сбой.
- **`app-moderation-notice`** (`shared/`, на хабе через `app-deck-moderation`). `.notice.warning` с заголовком «Модерация»: «Колода скрыта из Сообщества» и/или
  «Материалы сняты по жалобе» с числом («Снято: 2 материала и 1 упражнение.»). У чистой колоды ничего нет, сбой чтения тоже молчит (заметка не блокирует хаб).
  Ссылка уведомлений ведёт на `/decks/{id}#moderation`, фокус идёт на заголовок. О жалобе и о том, кто пожаловался, не говорится ничего.
- **Кабинет владельца `/manage/complaints`** ([кабинет](./admin-console-ux.md#жалобы)). Очередь и журнал используют общий `CursorList` и `app-auto-load`, без кнопок страниц; срок словами
  («Просрочена на 3 дня», «Срок через 12 дней», единица склоняется, без «дн.»), решение с подтверждением по образцу блокировки аккаунта (предупреждение «…? Решение попадёт в журнал.» и «Подтвердить …» / «Отмена»,
  без `confirm()`), выбор снимаемого: флажки `.check-row` в двух `fieldset.check-group` с `legend` («Материалы колоды», «Упражнения колоды»). «Вернуть в Сообщество» есть только там, где его принимает API: жалоба решена как «Скрыть» и колода скрыта сейчас (иначе `409 COMPLAINT_NOT_HIDDEN`).

Поле промокода показывает ответ сервера: доступ до даты без автопродления или скидку на будущую оплату.
При неизвестном результате оно повторяет ту же команду и не обещает, что тариф не изменился.
Промо-окно появляется только в разрешённой паузе, закрывается по Esc и явной кнопке; частоту ограничивает
решение текущего аккаунта в памяти и sessionStorage, а cooldown и окончательный отказ проверяет сервер.
Запись закрытия или отказа подтверждает только `Promo-Event-Recorded: true`, а не сам статус 204.
Пока подтверждения нет, браузер хранит только id кампании и выбор аккаунта,
не показывает новое предложение и повторяет запись в следующей разрешённой паузе. Явный отказ сохраняется
в этом браузере и после подтверждения; недоступное хранилище ограничивает эту защиту текущей вкладкой.

### Знакомство (spotlight-тур)

Источники: [ADR-ONB-001](../engineering/onboarding/adr/adr-onb-001-tour-engine.md), [architecture §8](../engineering/onboarding/architecture.md#8-frontend),
утверждённый вид — [прототип](../../design/prototype/onboarding/README.md) (design evidence, не архитектура). Движок — `frontend/src/app/core/onboarding/`,
элементы — `frontend/src/app/shared/`, примеры — раздел «Знакомство» (`sg-tour`). Новых зависимостей нет: нативные `<dialog>`, `inert`, `ResizeObserver`.

- **Карточка шага `app-tour-card`.** `<dialog role="dialog">`, имя — заголовок шага (`aria-labelledby`), описание — текст (`aria-describedby`); рубрика `.eyebrow`
  «Шаг N из M», точки шагов (только для глаз), «Назад» / «Дальше» и «Завершить знакомство». Информационный шаг открывается `showModal()` (страница позади
  неактивна, Tab остаётся в карточке); шаг, который закрывается действием на цели, — `show()`: «Дальше» нет, подсказка «Нажмите «…», чтобы продолжить»,
  остальная страница `inert`, кроме цели, карточки и тостов. Esc (и `cancel` диалога) ставит тур на паузу, не закрывает его; клик по вуали ничего не делает.
  Мини-слайдер — 2–3 пояснения одного места внутри шага (не новые шаги). Ключевые слова — `<span class="key">`: полужирный ink, в forced-colors подчёркнуты;
  текст шага разбирается в сегменты (`core/onboarding/tour-rich-text.ts`) и выводится узлами текста, не как HTML. Шаг без цели через 4 с показывает
  «Этого места сейчас нет на экране…» и даёт идти дальше; пока приложение готовит страницу — «Готовим колоду…» без «Дальше».
  Карточка до 37,5 rem шириной — нижний лист, а цель прокручивается выше листа; шире — плавает рядом с целью (сторона цели, противоположная, другая ось).
  Образец в стайлгайде рисуется в потоке (`inline`), не как открытый `<dialog>`: открытый диалог откладывает все тосты страницы.
- **Вуаль `app-tour-scrim`.** Один SVG-путь по правилу even-odd (весь viewport минус вырез с отступом 8 px и скруглением `--mn-radius`) цвета `--mn-scrim`;
  вырез не закрашен, поэтому цель принимает нажатия, а клик по вуали — нет. Рамка `--mn-star-lavender` стоит у выреза. В forced-colors вуаль прозрачна, а вокруг цели
  рамка `Highlight`. Положение — `ResizeObserver` цели и карточки, resize и scroll, склеенные в один `requestAnimationFrame`.
- **Ночная поверхность `app-night-sky`.** Фон `--mn-night` для приветствия и поздравления с проецируемым содержимым; звёзды мотива `app-deck-constellation`
  (лавандовые и бумажные) — только у них, опрос и выбор пути — тот же фон `[stars]="false"`. Мерцание конечное (три цикла по 3,6 с, затем покой), при уменьшенном движении
  звёзды неподвижны, в forced-colors фон `Canvas` без звёзд; звёзды `aria-hidden`. Классы содержимого на ночи (`h1`/`h2`, `.eyebrow`, `.lead`, `.muted`, `.button`) —
  в `components.css` под `app-night-sky`.
- **Опрос на ночи `app-survey-card`.** Бумажная карточка на ночной поверхности без звёзд: вопрос «Начала пути» с рубрикой «Вопрос N из 4» и полосой `role="progressbar"`
  (пройдено вопросов; вопрос, на который ответ уже есть, пропускается и оставляет в нумерации пропуск) или выбор пути без полосы. Заголовок принимает фокус при открытии;
  действия и строка о данных проецируются (`[actions]`, `[note]`). Экран «Начало пути» — полноэкранный модальный `<dialog>` (`features/onboarding/first-entry.component.ts`): звёзды только у приветствия.
- **Подсказка на месте `app-place-hint`.** Фраза у того, о чём она, без вуали (поиск Сообщества после 45 с без открытой колоды): `role="note"`, не берёт фокус.
- **Предложение тура `app-tour-nudge`.** «Не нашли подходящую?» через 2 минуты в каталоге: регион с заголовком, одно главное действие и «Назад», не модальное.
  Рисует его хост знакомства, а он, как и хост тура, помечен `data-tour-surface`: пока шаг с действием держит страницу `inert`, поверхности тура остаются живыми.
- **Пауза `app-tour-pause`.** «Знакомство на паузе» и «Продолжить знакомство»; фокус — на кнопке; продолжение возвращает на тот же шаг, фокус — на заголовок карточки.
  Та же плашка служит экрану «Начало пути»: Escape на карточке опроса или выбора пути (после начала, на приветствии паузить нечего) записывает PAUSE, закрывает экран, и
  «Продолжить знакомство» (RESUME) открывает ту же карточку; после перезагрузки плашка появляется сама, но фокус не берёт. Пока тур идёт, фокус остаётся у карточки шага и после
  перехода на страницу шага (оболочка не уводит его на заголовок страницы).
- **Завершение удержанием.** Вариант общего жеста `app-hold-to-delete-button`: `holdMs="2000"` (токен `--mn-tour-hold`), `armedGlyph="finger-hold"` вместо подписи без текста,
  `armedName` — доступное имя взведённой кнопки («Удерживайте 2 секунды, чтобы завершить знакомство»), `tone="ink"`. Размер кнопки при взведении не меняется.
  При уменьшенном движении (или `steppedFill`) заливка идёт четырьмя ступенями без анимации: во взведённом состоянии нет подписи с отсчётом, прогресс нужен иначе.
- **Тексты и анкоры.** Строки лежат в `core/onboarding/onboarding-texts.ts` (дословно из утверждённых текстов); цели регистрирует `mnTourAnchor="ключ"`, ключи — в
  `tour-anchor-keys.ts`, шаг — `StepKey` реестра контракта; `tourDefinitionProblems` и его spec сверяют определения тура с обоими реестрами. Событие для шага с действием
  публикует компонент цели через `TourEvents.emit('deck.copied')`, а не клик по DOM. `emit` возвращает `true`, если событие приняло шаг тура: тогда тур сам идёт на место
  следующего шага, а страница не переходит куда-либо сама (две навигации подряд отменяют друг друга); без тура страница идёт на своё место. Событие `study.started` публикует
  страница занятия, когда сервер открыл сессию, а не ссылка «Учить».
- **Озвучивание карточки тура.** «Шаг N из M» стоит в `aria-describedby` карточки вместе с телом и повторяется в вежливой области `role=status` внутри самой карточки: область
  вне модального `<dialog>` недоступна (`inert`) и молчит. Карточка не слышит Escape чужого диалога или меню: тур встаёт на паузу, только когда фокус в его поверхностях,
  на цели шага или на странице, нигде нет другого открытого диалога или меню и ключ не обработан. Открытие другого диалога на странице (жалоба) ставит тур на паузу.
- **Токены.** `--mn-night`, `--mn-on-night`, `--mn-on-night-muted`, `--mn-star-lavender`, `--mn-star-paper`, `--mn-scrim`, `--mn-glow`, `--mn-path-hover`, `--mn-night-wave`, `--mn-tour-hold`;
  пары на контраст (`color-contrast.spec.ts`): текст на ночи 16,9:1, вторичный 11:1, рубрика 8,3:1, ink на бумажной кнопке ночи 13,6:1, ink на заливке удержания 10,9:1;
  рамка выреза к странице под вуалью 3,9:1 (нетекстовая граница, порог 3:1).
- **Проверка.** Геометрия (вырез, сторона карточки, нижний лист, прокрутка) — чистые функции `core/onboarding/tour-geometry.ts` с числовыми тестами; jsdom без вёрстки,
  поэтому остальное видно только в браузере: раздел «Знакомство» в `ng serve` (development), 320 px без горизонтальной прокрутки. Харнес `scripts/browser-identity` собирает production-сборку
  без `/styleguide`, поэтому сценария для макета тура в нём нет.

Шапка (`core/layout/app-shell.component.*`) содержит бренд, навигацию и сессию; поиска в ней нет.
Поиск колод открывается в «Сообществе». Колокольчик, почта и «Выйти» выровнены в одну строку;

## Интересы и «Для вас» (Recs/1–3)

`app-interest-picker` — необязательный выбор интересов кнопками с `aria-pressed`. Сначала видны
направления существующего каталога; раскрытие показывает до пяти тем. Выбранная тема остаётся отдельной
кнопкой для отмены, а следующие предложения — детерминированные соседние ветви, без ML. Направления
служат только для навигации: сохраняются действующие leaf topic IDs. «Все темы» и постоянного счётчика нет.
На лимите 20 новые темы недоступны и появляется краткое объяснение; отмена выбора остаётся доступной.
Пояснение отделено от кнопок отступом; цели нажатия и текст центрированы. Выбор можно пропустить и позже
изменить в профиле. Серверный каталог сейчас содержит 54 выбираемые темы; добавление тем — отдельная миграция данных.
`app-interest-summary` сохраняет inline подтверждение сброса; `role=status` и возврат фокуса после закрытия формы остаются.

Заголовок каталога — «Колоды от сообщества». Между заголовком, поиском, интересами и пустыми состояниями
нет повторяющихся горизонтальных разделителей; границы полей и карточек сохраняются.

Приватная полка «Для вас» использует `app-deck-shelf`, строку «Потому что вы учите: …» из серверного `explanationTopic` и ссылку «Все» с `sort=for-you`. Показываются все 12 карточек, включая исследовательские места 11–12; при количестве меньше четырёх полка скрыта. Эти образцы первыми добавлены в раздел «Сообщество» `/styleguide`. Только вошедший читатель с разрешением сервера видит полку и сортировку; поиск без явно выбранной сортировки сохраняет близость к запросу.

Видимость карточек отслеживается через [Intersection Observer (W3C)](https://www.w3.org/TR/intersection-observer/) после рендера ([Angular afterRenderEffect](https://angular.dev/api/core/afterRenderEffect)); порог 50 %, один показ на код/поверхность/версию в навигации. Показы отправляются пакетами до 48 карточек через 300 мс или перед переходом, без опроса геометрии и постоянного хранилища. Гость и выключенная запись не создают наблюдатели телеметрии.

Для сетевого backpressure показы имеют четыре активных запроса и буфер до 1000 видимых карточек; пока он заполнен, наблюдатели приостановлены и возобновляются для ещё видимых карточек после освобождения места. События перехода не сэмплируются по лимиту запросов, их попытки ограничены навигацией и сетевым таймаутом 5 с. Позиции после 1000 передаются как `null`.

Рекомендационная выдача тоже показывает серверное объяснение над сеткой. Onboarding и его пустая область `role=status` остаются смонтированными при обычной загрузке, поиске, фильтрации и переходе к sparse-списку. В настройках «Изменить интересы» переводит фокус на первый checkbox; «Отмена» отменяет несохранённый выбор и возвращает фокус к кнопке редактирования. Явный `sort=popular` сохраняется при очистке поиска и удалении устаревших фильтров. Буферы показов разделены эпохой навигации: повтор одного кода на новой странице никогда не попадает в пакет предыдущего перехода. Dedupe экспозиций очищается для карточек, ушедших из текущей разметки; уже принятые в очередь показы сохраняются до отправки.

Настройки интересов обновляют уже известный профиль один раз при входе в `/profile`, чтобы использовать свежие темы и `rowVersion` после копии, удаления копии или изменения цели. Начальный GET не дублируется; активный запрос и команда с неизвестным исходом сохраняются. Onboarding в Сообществе не опрашивает профиль при перезагрузках полок. При конфликте 412 сообщение прямо говорит, что сброс ещё не выполнен либо выбранные темы ещё не сохранены, и просит повторить действие по актуальному профилю.

## Публичный профиль

Имя пользователя доступно независимо от публичности, с короткой подписью о его роли для публичных колод.
Кнопка «Показывать мой профиль другим» имеет `aria-pressed`; только при включении появляются соединённые
переключатели «Имя», «Фото», «О себе». Они выбираются независимо: прозрачный фон, лавандовое наведение,
индиговая заливка выбранного состояния и видимый фокус. Правовые условия доступны в общей политике из футера;
серверные consent payload и `textVersion` сохраняются. Пример соединённых кнопок — раздел «Меню и окна».

## Чтение материалов и статистика

`app-reading-frame` располагает SVG-шевроны с углом 120° без фона и тела в боковых полях материала.
`position: sticky` держит их на половине высоты viewport в пределах родительского материала; ниже 70 rem
ссылки идут под материалом и не перекрывают текст. Несуществующий сосед отсутствует, ссылки имеют
имена «Предыдущий материал» и «Следующий материал», `rel=prev/next` и цель минимум 44 px. При переходе
в том же маршруте содержимое перезагружается с отменой старого запроса; фокус идёт к заголовку.
Соседи берутся отдельным owner-only GET из текущего counted member root, без передачи всего списка;
при несовпадении ревизии навигация скрывается с предложением обновить, документ остаётся доступным.
Контракт — [материалы колоды](../../contracts/decks/README.md#навигация-материалов).

`app-deck-insights` собирает пять графиков на одном листе: механики занимают две верхние колонки,
