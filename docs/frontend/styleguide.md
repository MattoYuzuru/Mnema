# Стайлгайд frontend

Живой каталог дизайн-системы Mnema — маршрут `/styleguide`. Каждый пример на нём — настоящий компонент
или класс приложения, а не копия. Визуальное направление и токены описывают
[design and experience](./design-and-experience-2026-09.md) и
[brand and UI contract](./mnema-brand-and-ui-contract.md); этот документ — про то, как ими пользоваться.
Исполняемые примеры находятся в `frontend/src/theme/tokens.css`,
`frontend/src/theme/components.css`, `frontend/src/app/shared/`. При расхождении с
принятым design-контрактом проверь причину и исправь канонический источник: код
сам по себе не отменяет принятую визуальную границу.

## Правила

1. **Бери из стайлгайда.** Для кнопки, сообщения, подсказки, поля, метки, пустого состояния, листа нужен класс или компонент из каталога.
   Не рисуй свой вариант в стилях страницы и не копируй чужой: страница добавляет только раскладку
   (`.actions .button { flex: 1 1 12rem }`), а не второй вид элемента.
2. **Новый элемент — сначала в стайлгайд.** Нужно то, чего в каталоге нет: добавь пример и подпись «когда использовать»
   на страницу `/styleguide`, затем используй на экране. Если элемент общий, он живёт в `src/theme/components.css`
   (простые классы) или `src/app/shared/` (компоненты с поведением), а не в файле одной страницы.
3. **Только токены.** Цвета, отступы и радиусы — `--mn-*`. Hex, `px`-радиусы и теневые наборы в стилях компонентов не добавляются.
4. **Один главный приём на экран.** `.generate-cta` не больше одного, необратимое удаление — только `app-hold-to-delete-button`.
5. **Доступность — часть примера.** Область нажатия не меньше `--mn-touch-min`, фокус виден, статус назван словами,
   `forced-colors` и reduced motion не ломают смысл. Пример, не проходящий это, не попадает в каталог.

Тёмной темы и режимов плотности в продукте нет: страница не имеет их переключателей и честно об этом говорит.
Для движения есть переключатель «Спокойное движение»: он показывает вид страницы при reduced motion независимо от системной настройки.

## Длинные списки и автоподгрузка

Для длинных списков контента принят infinite scroll с опережающей загрузкой. Сетевой API остаётся
пагинированным: ограниченная порция, стабильный курсор, проверка контекста/ревизии. В интерфейсе нет
обычных кнопок «Показать ещё», номеров страниц или предыдущей/следующей страницы. Пользователь
читает и прокручивает один непрерывный список. Это правило действует для материалов, библиотеки
колод, упражнений материала, Capture, прогресса Study, уведомлений, событий, мастерских и списков кабинета
владельца (пользователи, промокоды, очередь обращений, журналы, сообщения тикета; общий помощник `features/admin/cursor-list.ts`).

Общий элемент — `shared/auto-load.component.ts` (`app-auto-load`); исполняемый пример со своей
прокруткой и имитацией сетевой ошибки находится в разделе «Обратная связь» `/styleguide`.

- Передайте `content` — DOM-элемент именно списка, `continuation` — следующий курсор, `loading`,
  `error`, а в `(loadNext)` подключите загрузку. Для отдельного scroll-контейнера задайте `root`;
  скрытый popover отключайте через `enabled`.
  При полной замене snapshot с сохранением того же DOM/курсора меняйте `context`; это явное начало нового списка,
  а повторившийся курсор обычного ответа сам по себе не запускает бесконечную цепочку запросов.
- Запас наблюдателя — 25% текущей высоты списка. Следующая порция запрашивается, когда нижний край
  viewport достигает примерно 75% загруженного содержимого. Для короткого списка запас не меньше
  одного viewport, чтобы заполнить доступное место. Высота пересчитывается после подгрузки,
  изменения ширины и увеличения текста. Статистика и заголовки вне списка на порог не влияют.
- Владелец данных допускает один запрос, добавляет строки по стабильному id без дублей, отменяет
  или игнорирует ответ старого контекста. На конце (`continuation = null`) запросов больше нет.
- Подгрузка сохраняет строки, выбор и текущий фокус. Статус загрузки озвучивается через `role=status`.
  Ошибка сохраняет прочитанное, останавливает автоповторы и показывает единственную кнопку «Повторить».
  Во время повтора кнопка остаётся на месте (`aria-disabled`), а после успешного повтора с клавиатуры фокус переходит
  на первую новую строку. Владелец, который перезагружает список, держит старые строки до ответа и меняет `context`.
- Подвал страницы за бесконечным списком доступен через вторую skip-ссылку оболочки «К подвалу: документы и поддержка».
- В хабе материалы загружаются по 50. Порция — параметр конкретного списка в пределах API,
  а не причина сразу скачивать всю колоду. Для длинных рядов используйте браузерную отсрочку
  отрисовки невидимого содержимого или обоснованную виртуализацию, с проверкой клавиатуры,
  выбора, фокуса, enlarged text и фактической геометрии в браузере. DOM и accessibility identity
  строк хаба сохраняются; `content-visibility: auto` сокращает работу layout/paint вне viewport.
  Резервная intrinsic-высота учитывает content box; декорация/tail/панель действий исключены из scroll anchoring.
  Браузерная проверка сравнивает положение читаемого материала до/после добавления страницы, а не только `scrollY`.

Пейджер партии генерации и переход между отдельными объектами выбирают рабочий объект;
они сохраняются. Их не следует использовать для продолжения каталога.

Решения опираются на [Angular afterRenderEffect](https://angular.dev/api/core/afterRenderEffect)
(наблюдатели устанавливаются после render и снимаются с контекстом),
[Intersection Observer](https://www.w3.org/TR/intersection-observer/)
(опережение задаётся `rootMargin` в px, рассчитанным из высоты списка) и
[CSS Containment](https://www.w3.org/TR/css-contain-2/#content-visibility)
(невидимое содержимое можно пропускать при layout/paint, сохраняя доступность при `auto`).
Декорация исключается из anchoring по [CSS Scroll Anchoring](https://www.w3.org/TR/css-scroll-anchoring-1/#exclusion-api),
чтобы изменение высоты страницы удерживало читаемый материал, а не звёзды на её полях.

## Как открыть

В полном локальном стеке включите development-сборку frontend, сохраняя текущие
аккаунты, материалы, сертификаты и порты:

```bash
MNEMA_LOCAL_FRONTEND_CONFIGURATION=development ./scripts/mnema-local-full-stack.sh start
```

Откройте [Style Guide в локальном стеке](https://localhost:3443/styleguide) (если при
bootstrap выбран другой `MNEMA_LOCAL_WEB_PORT`, используйте этот сохранённый порт).
Это тот же runtime, а не второй набор данных. На следующих `start` повторяйте флаг,
пока нужен каталог. Для возврата к production-сборке:

```bash
./scripts/mnema-local-full-stack.sh start
```

Только каталог без Docker/backend можно открыть отдельным dev-сервером:

```bash
(cd frontend && npx ng serve --host 127.0.0.1 --port 4200)
```

[Style Guide без backend](http://localhost:4200/styleguide) использует локальные
фикстуры и не требует входа. `npm start` в проекте нет; цель `serve` в
`frontend/angular.json` по умолчанию собирает `development`. Остановите dev-сервер
через Ctrl+C.

Production и обычный локальный `start` отдают production-сборку (`npm run build`),
поэтому `/styleguide` там **нет**. Флаг работает только с
`deploy/local-full-stack/frontend.Dockerfile` и допускает `development` или
`production`; release Dockerfile его не использует. Это следует Angular
[build configurations](https://angular.dev/tools/cli/environments) и Docker
[build arguments](https://docs.docker.com/build/building/variables/).
Подробнее о данных и портах: [локальный runtime](../deploy/selfhost-local.md).

## Почему страницы нет в production

`app.routes.ts` регистрирует маршрут только при `typeof ngDevMode === 'undefined' || ngDevMode`. Сборщик приложения Angular
в конфигурации `production` (`optimization.scripts`) определяет `ngDevMode` как `false`, esbuild убирает условие вместе с
динамическим `import()`, и ни маршрут, ни чанк страницы в бандл не попадают. `isDevMode()` — вызов времени выполнения и код бы оставил.

Проверка выходного каталога после `npm run build`:

```bash
cd frontend
node scripts/verify-no-styleguide.mjs              # dist/mnema-frontend; exit 0 — страницы нет
npx ng build --configuration development && node scripts/verify-no-styleguide.mjs   # обязан упасть: проверка честная
```

Скрипт ищет в файлах сборки имя `styleguide`, компонент и русские тексты страницы. Юнит-тест `app.routes.spec.ts`
фиксирует, что в development-сборке маршрут есть, ленивый и без `canActivate`.

### Выбор из сегментов в режиме forced-colors

`app-segmented-choice`: выбранный сегмент не должен зависеть от заливки `Highlight`. Chrome подкладывает под такой текст подложку Canvas, и подпись
`HighlightText` превращалась в белый прямоугольник. В `forced-colors` все подписи `ButtonText` на `Canvas`, выбор показывают закрашенный кружок
(`Highlight`) и контур `Highlight`; контракт закреплён в `segmented-choice.css.spec.ts`, вид проверен в Chrome с эмуляцией `forced-colors: active`.

### Меню действий «⋯» и «Поделиться»

- **`app-action-menu`.** Кнопка «⋯» и меню по шаблону [APG menu button](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/):
  `aria-haspopup="menu"`, `aria-expanded`, `aria-controls`, имя задаёт вызывающий («Действия с колодой «…»»). Меню — нативный
  `popover="auto"` ([MDN Popover API](https://developer.mozilla.org/docs/Web/API/Popover_API)): верхний слой, закрытие кликом вне и
  Esc. Enter, Пробел и ↓ открывают меню и ставят фокус на первый пункт, ↑ — на последний; ↑ ↓ (по кругу), Home, End и буква
  ходят по пунктам (та же буква ещё раз — следующий такой пункт); Esc и выбор пункта возвращают фокус на кнопку, Tab закрывает меню. Недоступные пункты пропускаются. Вход:
  `label`, `items` (`id`, `label`, `glyph?`, `disabled?`, `danger?`), выход `chosen` с `id`. Возле кнопки меню ставит CSS anchor
  positioning, без него браузер центрирует его в окне (как у `app-toggletip`). В меню только действия, которые уже работают.
- **«Поделиться».** `ShareLinkService.share(url, title)` вызывается прямо из обработчика клика (нужна активация пользователя).
  На телефоне (`(pointer: coarse)`, `navigator.share`, `canShare({ url })`) открывается системное меню
  ([Web Share API](https://developer.mozilla.org/docs/Web/API/Navigator/share)) только с `url` и `title`, без готового текста;
  закрытие меню без выбора (`AbortError`) молчит. Иначе ссылка копируется ([Clipboard API](https://developer.mozilla.org/docs/Web/API/Clipboard/writeText)),
  тост «Ссылка скопирована» (повтор заменяет прежний). Если буфер закрыт, появляется ошибка (`ToastService.echoError`: действие пользователя, а не уведомление, поэтому паузы занятия её не гасят) и результат `failed`: экран показывает ссылку в
  `app-share-link-field` (URL-поле только для чтения; когда оно появилось, фокус переходит в него, ссылка выделена, пояснение связано `aria-describedby`); `execCommand` не используется.
- **`app-public-deck-card`.** Каркас карточки каталога: данные `PublicDeckCard` (`shared/public-deck-card.ts`), «Добавили» и
  «Учат сейчас» показываются от 10 и округляются вниз до двух значащих цифр (`audienceCount`: 9 — скрыто, 10 → «10», 1234 → «1,2 тыс.»).
  Скрытый автор, пустые медиа и малые счётчики не рисуются. Короткая форма («1,2 тыс.») — для глаз, скринридер читает полную («1,2 тысячи»); тема и язык имеют невидимые «Тема:» и «Язык:»; уровень заголовка — вход `headingLevel` (2–4, по умолчанию 3); у каждого экземпляра свой id.

### Экран отказа и публичный просмотр колоды

- **`app-access-screen`.** Страница, которая объясняет, почему колоды не видно. Заголовок (`h1` по умолчанию, `headingLevel` 2–4 внутри страницы со своим `h1`;
  `tabindex="-1"`, чтобы оболочка и экран могли поставить на него фокус), одно короткое объяснение (содержимое по умолчанию) и действия, которые
  уже работают (слот `[access-actions]`: ссылка или кнопка). Мёртвых кнопок нет: «Запросить доступ» появится вместе с запросом доступа (TODO #435), «Добавить
  к себе» — вместе с копированием (TODO #432). Линии сверху и снизу, как у `.empty-state`; тон передают слова.
- **Публичный просмотр `/d/:код/:slug` и `/d/:код`** (`features/public-deck/`, без `authGuard`, гостям тоже) собран из каталога: шапка из `.eyebrow`,
  заголовка, метки уровня (`.stamp` со знаком `app-glyph`: «Публичная», «По ссылке», «По приглашению»), `app-author-chip`, `app-share-button` и
  `app-action-menu` (только «Поделиться»; «Пожаловаться» придёт с Share/15), `app-segmented-choice` («Материалы» и «Упражнения», подсказка «Показаны упражнения: N» озвучивается при выборе), списки `app-auto-load`
  без кнопок страниц, материал в `app-native-media-surface` (`audience="public"`, без `data-node-id`), экраны отказа выше. Новых общих элементов, кроме
  `app-access-screen`, этот экран не вводит; заголовок хаба и строки списков живут в файлах страницы, как раскладка.
- **Адрес.** Slug есть только у PUBLIC-колоды; неверный или отсутствующий slug заменяется на канонический (`replaceUrl`), у LINK и INVITE slug не показывается.
  Материал открывается в той же странице как `?material=`, так что «Назад» возвращает к списку.
- **Голова страницы.** Пока маршрут активен, стоит `<meta name="referrer" content="no-referrer">`, а `robots: noindex` стоит, пока колода не загружена и
  не оказалась PUBLIC (LINK, INVITE и все экраны отказа не индексируются); при уходе `robots` возвращается к `index,follow` из `index.html`, а политика реферера сначала ставится в `strict-origin-when-cross-origin` (заголовок nginx, [browser security headers](../operations/browser-security-headers.md)) и только потом тег убирается: Chrome держит последнюю применённую политику. Внешние ссылки в материале
  имеют `rel="ugc nofollow noopener noreferrer"`. OG-карточка и серверный `X-Robots-Tag` — Share/14.
- **Список и материал.** Список материалов остаётся смонтированным (скрытым), пока открыт материал: «Назад» возвращает те же строки, курсор и место.
  На странице материала есть «Предыдущий» и «Следующий» (соседей список дочитывает сам, не больше 20 порций), заголовки документа лежат ниже `h2` материала
  (`headingOffset`: уровень 1 документа становится 3). После 412 список читается с начала, статус «Автор обновил колоду…» — постоянный `role=status`, голова списка
  прокручивается в видимую область. «Повторить» после 429 имеет `aria-disabled` до конца `Retry-After` (с обратным отсчётом в тексте).
- **Клавиатура и скринридер.** Фокус после загрузки и смены экрана переходит на `h1` страницы, при открытии материала — на его заголовок «Материал N из M»
  (`tabindex=-1`), при возврате в хаб — на строку, которая была открыта (всё это, если читатель сам не увёл фокус); список —
  `ol` с одной ссылкой на строку (вся строка кликабельна растянутой ссылкой, фокус виден контуром), продолжение списка озвучивается через `role=status`,
  ошибка — одна кнопка «Повторить»; уровень доступа читается словом («Доступ: Публичная»), а не значком.

Поле промокода показывает ответ сервера: доступ до даты без автопродления или скидку на будущую оплату.
При неизвестном результате оно повторяет ту же команду и не обещает, что тариф не изменился.
Промо-окно появляется только в разрешённой паузе, закрывается по Esc и явной кнопке; частоту ограничивает
решение текущего аккаунта в памяти и sessionStorage, а cooldown и окончательный отказ проверяет сервер.
Запись закрытия или отказа подтверждает только `Promo-Event-Recorded: true`, а не сам статус 204.
Пока подтверждения нет, браузер хранит только id кампании и выбор аккаунта,
не показывает новое предложение и повторяет запись в следующей разрешённой паузе. Явный отказ сохраняется
в этом браузере и после подтверждения; недоступное хранилище ограничивает эту защиту текущей вкладкой.

класса. Исключайте общий класс (`p:not(.eyebrow)`) или не пишите правило на элемент.
