# Mnema: бумага, память и собственный способ учиться

Документ фиксирует подробное визуальное и продуктовое уточнение владельца
2026-09-06. Третье присланное изображение принято как направление: тёплая фактурная
бумага, насыщенные чернила индиго, античная гравюра Мнемозины, выразительная книжная
типографика, облака, звёзды, пунктирные орбиты и небольшие бумажные выноски.
Это потребительский учебный продукт для первого русскоязычного web-релиза.

Продуктовые состояния и допустимые переходы определяет
[authoring-and-study-workflows](../product/authoring-and-study-workflows.md).
Модель содержания задаёт [learning-content-format](../architecture/learning-content-format-v2.md),
границы сервисов и ревизий — [content-platform](../architecture/content-platform-v2.md).
Этот документ определяет их представление в UI. Рабочий
[интерактивный прототип](../../design/prototype/README.md) создан отдельно от текущего
Angular приложения. Исходный архив Downloads прочитан и сохранён без изменений.

## Принятые решения и предлагаемые детали

| Решение владельца | Конкретизация в макете / статус |
|---|---|
| Именно третье изображение и бумажная античность | Cream paper + ink indigo + новая растровая гравюра; направление принято |
| Весь продукт должен соответствовать направлению | Лендинг выразительный, редактор и занятие спокойнее, но фактура и типографика общие |
| Русский B2C, собственные материалы и гибкие упражнения | Русские тексты без research/product/docs и рекламных обещаний AI |
| Гибкая прокручиваемая landing page | Незакреплённая шапка предложена как начальный вариант; футер внизу после разделов |
| Кликабельные смысловые блоки | Настоящие anchor links; цвет, подчёркивание и спокойная заливка только для самостоятельных плиток |
| Без чужого каталога на первом макете | Создание своей колоды; sharing/catalog/onboarding из каталога — следующий этап |
| Нейтральное приятное название быстрых записей | «На потом» — предложение; без Inbox и дополнительного брендинга «библиотека/атлас» |
| Материал ≠ двусторонняя карточка | Длинный документ рядом с независимыми представлениями упражнений |
| Подтверждённое сохранение делает правку доступной | Автор видит несохранённые правки, pending и номер сохранённой редакции |
| Дополнительные повторения без эффекта на основной результат | Отдельная текстовая пометка и отсутствие прироста прогресса |

Сравнение новых направлений здесь не требуется: владелец уже выбрал референс.
Прежний Liquid Glass, градиентные SaaS карточки и смысл «исследовательская доска с AI»
отвергнуты. Созданные макетом размеры, длины подписей и шрифт — проверяемые
предложения, а не утверждённые владельцем API лимиты.

## Визуальная система

| Token / мотив | Значение и применение |
|---|---|
| `paper` | `#f4f0e5`, основной фон с лёгким статичным зерном |
| `sheet` | `#fbf8ef`, отдельный лист/редактор/упражнение |
| `ink` | `#281378`, заголовки, действия, линии и знаки |
| `body` | `#342e44`, основной текст |
| `muted` | `#625c70`, пояснения; не снижать opacity текста |
| `line` | `#c9c0ce`, тонкое разделение; не единственный признак интерактивности |
| `soft` | `#e8e1ed`, выбранное действие и информационная заметка |
| Display serif | Cormorant Garamond с кириллицей, variable weight 300–700; Georgia fallback |
| Reading / controls | Системный sans, длинный предпросмотр допускает Georgia; поля минимум 16 px |
| Microcopy | Системный mono для коротких номеров и рубрик; не длинных инструкций |
| Spacing | Базовый шаг 4/8 px; 18–24 px mobile gutters, 44 px desktop gutters |
| Geometry | Почти прямые углы, 1 px правила, тень только у наложенного бумажного листа |
| Motion | Функциональный anchor scroll; без параллакса, движущегося зерна и вращения звёзд |

Шрифт получен из [официального google/fonts](https://github.com/google/fonts/tree/main/ofl/cormorantgaramond),
SIL OFL включена рядом с файлом. Он выбран за контрастный античный рисунок и русские
буквы; это не подтверждение соответствия каждой детали исходному латинскому шрифту.
В production нужен локальный WOFF2 с кириллицей/латиницей, `font-display: swap`,
проверка переноса длинных русских заголовков. Не подгружать шрифты с внешнего CDN
без отдельного решения. Системный sans держит форму, навигацию и чтение устойчивыми.

Переиспользуемые компоненты: PaperSurface, EngravingPanel, StarMark, CelestialCloud,
OrbitRule, AnnotationLink, TextNavigationLink, FeatureAnchor, RuledList,
DeckHeading, CaptureComposer, SaveState, MaterialPreview, ExerciseProjectionEditor,
StudyFrame, MatchPairButton, SessionModeChoice. Названия здесь технические, не UI.
Не объединять их в универсальную карточку с десятками флагов. Звёзды и облака
декоративны, недоступны фокусу и скрыты от screen reader. Ссылка с декором имеет
понятный текст; вся смысловая плитка активна без вложенной кнопки.

Гравюра: сохранить штрих, бумажные светлые участки, глаза без нарисованных зрачков,
античную пластику и образ богини памяти. Владелец просит более гармоничное,
мягкое модельное лицо, менее грустное выражение, аккуратнее нос, высокую детализацию.
Новая версия — 1024×1536 raster на сплошном индиго; «почти векторная чёткость» означает
качество, а не перевод в SVG. Greek caption поддерживает эстетику, но русский текст
объясняет смысл. Не отдавать существенные надписи частью картинки. На мобильном
портрет стоит после главного действия и не мешает первому чтению.

Фактура не исчезает на внутренних страницах. При этом документу не мешают облака
за каждой строкой: максимальная декоративная плотность у лендинга, заметно меньше
у колоды, минимум у упражнения. Фон статичный, opacity низкая, без фильтров на тексте.

## Лендинг: структура и готовые тексты

Шапка: `MNEMA` → главная; `Материалы`, `Упражнения`, `Как учиться` → соответствующие
разделы; `Попробовать →` → демо своих колод. Header не sticky, чтобы композиция
напоминала страницу книги; production дизайнер может изменить это после проверки
длинной страницы на мобильном. Навигация меняет цвет/подчёркивание, не ширину шрифта,
поэтому соседние ссылки не скачут и не превращаются в hover pills.

Hero: «Учиться. Понимать. Помнить.» Пояснение: «Ваши материалы и упражнения — в одном
месте. Собирайте важное, учитесь по-своему и возвращайтесь к знаниям вовремя.»
Главное действие: «Начать с моей колоды →». Вторичное: «Как это устроено».
Рядом портрет; бумажная выноска «Ваши знания. Ваши упражнения. Ваш ритм.» ведёт к
упражнениям. Выноска «Память — это больше, чем хранение. Это понимание.» ведёт к
ритму обучения. Владелец одобрил композиционную роль подобных маленьких блоков;
новая русская редактура заменяет общий текст про advantage/context.

Три кликабельных плитки: «Всё важное рядом» → материалы; «Упражнения под вас» →
упражнения; «Помнить надолго» → практика. Иконки входят в единую область нажатия.
Ни одна плитка не обещает недоступную функцию. Далее идут три полноценных секции:

1. «Мысль — короткая. Знание — глубокое.» Быстрая запись, полноценный материал,
   смешанная колода и образец Serendipity. Действие открывает English deck.
2. «Не всё знание помещается на карточке.» Материал и его короткие проекции,
   разные способы упражняться. Действие открывает редактор.
3. «В своём темпе. С местом для повторения.» Занятие, повтор снимка и свободная
   практика без изменения расписания. Действие открывает демонстрационное занятие.

Финальная секция: «Оставьте место любопытству.» → создать свою колоду. Настоящий
футер после содержимого: Mnema и смысл продукта. Пока нет опубликованных юридических
страниц/каналов, не рисовать мёртвые ссылки и не переносить из референса недоказанные
«secure by design / private by default / your own data». Production футер обязан
подключить действительные контакты, документы и применимые privacy controls до запуска.
Каталог сообщества, лайки и маркетинговое «у нас уже много качественных колод»
появятся после реального запуска и наполнения соответствующих функций.

## Информационная архитектура и связные сценарии

```text
Лендинг
└── Мои колоды / Создать колоду
    └── Выбранная колода
        ├── Материалы → материал / редактор / представления упражнений
        ├── На потом → разбор → сохранённый материал
        └── Занятие → завершение
            ├── Вернуться к материалам
            ├── Повторить сегодняшнее занятие
            └── Потренировать всю колоду
```

Колода — единица контекста. Начало занятия требует deck ID. Не проектировать
межколодный shuffle, общий due pool или один LearningItem, одновременно доступный
для редактирования в нескольких колодах. Название материала и его описание
пользователь определяет сам; слова, правила, конспекты, примеры и медиа могут быть
соседями. Первый onboarding: создать колоду → добавить материал → настроить первое
упражнение → попробовать занятие. Будущий onboarding из каталога — отдельная ветка.

«На потом»: заметка сохраняет намерение до явного удаления, показывает `createdAt`,
не имеет scheduler state и не участвует в учебных рекомендациях. Накопление заметок
можно мягко подсвечивать: «Здесь есть мысли, к которым вы давно не возвращались».
Не наказывать streak и не называть это просроченным долгом. Разбор может закончиться
материалом, архивированием или осознанным удалением. В макете реализована конверсия
в материал; production должен добавить редактирование, архив, подтверждаемое удаление.

EditingDraft отличается от заметки «На потом»: автоматическое восстановление
несохранённой правки не публикует новую редакцию. В production сервер хранит несколько
черновиков разных документов/вкладок с optimistic concurrency; сроки, ограничения
и storage описывает продуктовый/архитектурный контракт. UI показывает «Черновик
восстановлен», время последнего успешного autosave, «Не удалось сохранить черновик —
повторить» и конфликт версий. Уход со страницы при несохранённом или ещё не подтверждённом
draft требует понятной возможности остаться/уйти. Не представлять localStorage или
Redis TTL как доказательство безопасности/долговечности. Прототип честно использует
только память демо, без обещания такого восстановления.

## Редактор и упражнения

Production desktop сохраняет принятый split editor слева / live preview справа;
настройки упражнений — отдельный inspector/tab, не обязательная третья узкая колонка.
В компактном standalone макете preview раскрывается под текстом, а упражнения справа:
это упрощение демонстрации, не отмена split-preview требования. На mobile — последовательный
доступ или переключатели «Материал / Вид / Упражнения», сохраняющие ввод и фокус.
Основное сохранение всегда ясно видно,
но не перекрывает содержание. Ответы в упражнении не навязывают фронт/бэк документу.

Пример материала: главное слово, перевод, три предложения, три перевода, YouTube URL,
загруженное видео, два варианта произношения и длинная заметка. Для одного упражнения
пользователь выбирает слово и один пример; для matching — короткое слово и перевод;
для аудирования — аудио; для объяснения — вопрос и rubric. Фото/audio/video входят
в базовую модель. Mermaid и другие форматы расширят palette позже. Native media
controls, понятные альтернативные тексты и captions/transcript предусмотрены в UI
контракте; реальная медиа-загрузка в этом прототипе не реализована.

Связь упражнения с материалом хранит item ID, revision, стабильные node selections,
роль и display projection. Одно упражнение может использовать несколько материалов;
один материал — несколько упражнений. Пользователь может выбрать и нетипичный материал,
если он явно задаёт совместимую проекцию. Допуск строится по явным bindings, а не по
жёсткому классу «слово/грамматика». В демонстрационном matching выбран vocab-only subset
из двух слов; это пример настройки, не глобальное ограничение модели.

Matching показывает две компактные колонки. Выбрать слева, затем справа можно pointer,
tap, Tab/Enter/Space; drag не обязателен. Выбранная пара имеет текстовый/графический
признак, правильная — галочку и текстовое сообщение; цвет не единственный сигнал.
Неверная пара оставляет выбор исправимым. Screen reader получает состояние и результат.
Не помещать весь многосотсловный материал в label и не решать это вложенным скроллом.
Валидировать ограничение renderer заранее; предложить короткую custom подпись или
выбор другого фрагмента. Для audio mapping размер определяется control/длительностью,
а не текстовой длиной. Prototype caps 160/240 — только пример для двухстороннего recall;
production matching требует отдельного более компактного schema limit и preview.

Ревизия после save меняется логически. UI не должен внушать, что сохранение одного
перевода копирует все материалы колоды или обнуляет освоение. «Учить заново» — явное
отдельное действие над материалом с подтверждением последствий; его нельзя скрыто
вызывать при редактировании правильного ответа. Старые попытки показывают тот ответ,
который был действителен в сохранённой версии сессии.

## Занятие, завершение и дополнительная практика

В обычном занятии пользователь решает разные упражнения из одной колоды. Двухстороннее
вспоминание — один renderer, интервальное расписание — механизм отбора/планирования.
Не изображать mastery достоверным процентом лишь из числа кликов. Полный продукт
показывает понятную сводку материала из заданной моделью оценки; исторические ответы
и типы evidence остаются различимыми. Субъективное «учить заново» не стирает историю.

После завершения показать три действия: вернуться, повторить сегодняшний снимок,
потренировать колоду. Повтор снимка фиксирует опубликованные revision и порядок.
Свободная практика работает по выбранному deck snapshot + seed, может начинаться
с более слабых уже изучавшихся материалов; включение новых должно быть явным выбором.
Это не экран выбора «каноничная/неканоничная сессия»: назвать смысл по-человечески.

Оба дополнительных режима не меняют schedule, mastery, streak и обычные счётчики.
Можно закончить и повторить их сколько угодно. При этом нельзя блокировать реальные
due, появившиеся позднее в тот же день: сообщение «сегодня занимались» не является
жёстким календарным запретом на очередное назначенное повторение. В прототипе дата и
due не моделируются, поэтому completion flag — лишь демонстрация ветки после занятия.

Огромная колода: запрос всей практики создаёт ограниченную порцию/session handle;
клиент не загружает все материалы и медиа ради первого экрана. Продолжение — cursor,
стабильный seed и version, без повтора уже выданных позиций при retry. В UI задаётся
разумная длительность/объём, видна пауза/выход/продолжение, никто не обязан «закончить
всю колоду». Прототип честно выдаёт 2–3 задания и не является реализацией такого обхода.

## Состояния, доступность и production переход

| Поверхность | Обязательные состояния |
|---|---|
| Мои колоды | Loading, пусто, список с cursor, ошибка/повтор, недоступная колода |
| Создание | Пустое/пробельное имя, отправка с защитой от повтора, серверная ошибка с сохранённым вводом |
| Материал | Saved, dirty, autosaving draft, recovered, conflict, save pending, error/retry, отсутствующий asset |
| На потом | Пусто, подтверждённая запись, retry без дубля, разбор, archived, delete/undo policy |
| Упражнение | Нет binding, несовместимая/слишком длинная проекция, удалённый узел, preview, validation |
| Study | Нет допущенных материалов, подготовка порции, render failure/retry, answer pending, завершено, повтор |
| Media/offline позже | Download progress, объём, недоступный внешний embed, expired access, sync conflict и retry |

Реализованные в макете состояния перечислены в README. Матрица выше — требования
production, не заявление о готовности каждого состояния. Процессы авторизации,
ownership checks, real latency, permission loss и server conflicts требуют API.

Семантические ссылки/кнопки/labels; один main и h1 на экран; focus переносится при
навигации и остаётся предсказуемым при reveal/matching. Skip link ведёт к содержимому.
Проектный touch target 44–46 px; WCAG 2.2 AA minimum имеет порог 24 px и исключения,
поэтому не называть 44 px обязательным порогом AA. Выбор target и видимого фокуса
опирается на [W3C Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
и [W3C Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html).
Проверять contrast всех важных состояний, увеличение текста и ширину 320 CSS px;
не обрезать текст ради макета. Reduced motion убирает smooth scroll. Нужны реальные
VoiceOver/TalkBack/Safari проверки перед production, один Chromium не заменяет их.

Angular production: самостоятельные route components; Signals для локального
редактора/session view state, API client для серверного состояния; router и autosave
имеют ясные lifecycle boundaries. Сервер владеет draft IDs, revisions, session snapshots,
access и mutations. Использовать ограниченные query pages, abort stale requests,
idempotency keys и конфликт по ожидаемой версии. Не превращать demo `app.js` с глобальным
state в production module. Shared design tokens и проверенные компоненты переносить
по owning frontend epic, заменяя текущий канонический UI без /v2 параллельных маршрутов.

Предлагаемые performance budgets для production: критический текст/UI доступен без
ожидания гравюры; hero имеет явные размеры и responsive raster варианты; один
локальный subset serif, минимум начальных шрифтов; статичная texture до 10 KB;
загрузка списков/материалов и работа с документом ограничены порциями. Медиа лениво,
видео без autoplay. Точные latency/bundle thresholds согласовываются через измерения,
не объявляются гарантией highload. Полный TTF и PNG прототипа не оптимизированы для
производственного network budget.

### First useful screen and API shape

Публичный лендинг — кандидат на prerender/static delivery; авторизованная часть
не должна ждать персональных API ради общей шапки и навигации. Выбор SSR для private
страниц требует отдельного доказательства пользы и корректного cache/auth boundary.
В Angular лениво загружаются самостоятельные editor/study/admin routes через
`loadComponent`/`loadChildren`; тяжёлые редакторы math/code/diagrams и нижние разделы
могут использовать `@defer` по interaction/viewport. Не откладывать основной текст,
первое действие и критический renderer только ради формального количества lazy blocks.
Это следует [Angular lazy routes](https://angular.dev/guide/routing/loading-strategies)
и [deferred loading](https://angular.dev/guide/templates/defer); framework version
проверяется перед implementation, а не наследуется из старого Angular 18 checkout.

API needs: список колод возвращает cursor page компактных summaries, не все items;
страница колоды отдельно получает header/доступ и первую страницу материалов;
открытый материал — явную revision и content capabilities; start Study — session
handle и первую bounded batch; job status и optional statistics загружаются независимо.
Никакого per-deck N+1 ради счётчиков и одного общего loading gate на весь экран.
Ошибка вспомогательной статистики не скрывает сохранённый материал/основное действие.
Точные URLs/DTOs остаются #74/#75 LLD, не прототиповым публичным API.

Измерять first useful content, route bytes, LCP/INP/CLS, request fan-out и p95/p99 API
при явном профиле устройства/сети. Предлагаемые web quality ориентиры — p75 LCP ≤2.5 s,
INP ≤200 ms, CLS ≤0.1; это [Core Web Vitals](https://web.dev/articles/vitals), не
обещание «всегда мгновенно» и не результат измерения этого макета. Lazy frontend
уменьшает ненужную работу клиента, но сам по себе не гарантирует high-load backend.

## Следующие этапы и границы

Sharing, быстрые личные clones/forks, upstream changes preview, manual clean pull,
разрешение сложных конфликтов и PR — будущие UX-потоки поверх предусмотренной модели
происхождения и ревизий. В этот макет не включены; не занимают навигацию первого запуска.
Каталог, качественные колоды сообщества, лайки/ранжирование и рекомендации — после
проверки собственно обучения. Финансовая гипотеза лимита своих/клонированных колод
не превращается в текущий paywall; окончание подписки не удаляет созданные материалы.

Native iOS/Android и скачивание колоды с медиа для offline practice — будущий продукт.
В UI нужны offline status, sync state, timestamp и объяснение конфликтов; решение
о платности offline не принято. Web-only первого релиза не обещает offline работу.
