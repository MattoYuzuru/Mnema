# Mnema — бренд и контракт интерфейса

Этот документ — проверяемые правила для изменений production frontend. Он не меняет
продуктовую модель, API, доступность функций или права пользователя. За поведение
материалов и занятий отвечают [product workflows](../product/authoring-and-study-workflows.md)
и действующие контракты. Здесь определено, **как** показывать это поведение.

## Источники и границы

При расхождении источников применять их в таком порядке:

1. Текущие продуктовые и архитектурные контракты определяют реальные функции и состояния.
2. [Принятое направление от 2026-09-06](design-and-experience-2026-09.md) задаёт
   визуальную идентичность и композицию. [Прототип](../../design/prototype/README.md),
   его [desktop](../../design/prototype/screenshots/01-landing-desktop.png) и
   [mobile](../../design/prototype/screenshots/05-landing-mobile.png) снимки —
   визуальные свидетельства, но его JavaScript, данные и роутер не являются production-кодом.
3. [Присланное владельцем изображение](https://chatgpt.com/share/6aba8313-3b68-83eb-95ab-97f7fa520df1)
   и ранний чат объясняют вдохновение: редакционная неоклассика, гравюра, дуотон,
   журнальная сетка. Это ранний brainstorming, а не спецификация Mnema. Ссылка
   прочитана в браузере 2026-09-28; изображения пользователя в чате и текущем запросе
   служат визуальным референсом.

Из изображения сохраняются: открытая бумажная плоскость, индиговое поле с Мнемозиной,
крупный контрастный заголовок, тонкие правила и орнаменты, наложенные бумажные выноски,
ограниченная палитра и разная плотность левой и правой частей. Изображение **не задаёт**
английский текст, разделы `Research`/`Product`/`Docs`/`About`, `Request access`,
AI-обещания, ссылки на Twitter/Discord или заявления о приватности и безопасности.
Первый web-релиз — русскоязычный продукт для собственных колод и занятий. Ссылки ведут
только к существующим маршрутам и функциям. Новая маркетинговая формулировка не может
подменить фактическое состояние продукта.

## Визуальная идея

Mnema выглядит как современное учебное издание, посвящённое памяти. Бумага и чернила
создают спокойное место для чтения; античная гравюра создаёт узнаваемую обложку.
На лендинге допустима выразительная композиция. В редакторе на первом месте текст
и сохранение. В занятии на первом месте вопрос, ответ и следующий шаг. Орнамент
снимается по мере роста когнитивной нагрузки.

Узнаваемость должна сохраняться без анимации и в чёрно-белом режиме: за счёт
иерархии, пропорций, типографики, сетки, правил и текстов. Не добавлять стеклянные
панели, большие скруглённые карточки, градиенты ради объёма, бессмысленные метрики,
многоуровневые тени, набор случайных иллюстраций, «технологические» микротексты
вместо полезных подписей или орнамент вокруг каждого элемента. Ранний Hermes-референс
не даёт права копировать его изображения или UI.

## Токены: единый источник

Production CSS custom properties живут в одном импортируемом файле токенов
(`frontend/src/theme/tokens.css` после переноса). Компоненты используют **семантические**
имена; исходные hex и размеры не повторяются в локальных стилях. `global_styles.css`
подключает токены, задаёт только reset, базовую типографику и общие состояния.
Контекстные исключения (например, текст на индиговом поле) оформляются как отдельные
семантические токены, а не локальная копия цвета. Изменение токена сопровождается
поиском всех его потребителей и проверкой контраста в состояниях. Старые `--glass-*`
и compatibility aliases удаляются после перевода их потребителей; их наличие сейчас
не определяет стиль.

| Слой | Токен | Значение / роль |
|---|---|---|
| Основа | `--mn-paper` | `#f4f0e5`, фон страницы |
| Основа | `--mn-sheet` | `#fbf8ef`, читаемый лист, поле, упражнение |
| Основа | `--mn-ink` | `#281378`, заголовки, ссылки, primary action |
| Основа | `--mn-body` | `#342e44`, основной текст |
| Основа | `--mn-muted` | `#625c70`, вторичный текст, не понижать opacity |
| Основа | `--mn-rule` | `#c9c0ce`, разделитель, **не** единственный индикатор границы поля |
| Основа | `--mn-soft` | `#e8e1ed`, selected/notice surface |
| Состояние | `--mn-positive` | `#326443`, подтверждение на светлом листе |
| Состояние | `--mn-danger` | `#962b31`, ошибка на светлом листе |
| Состояние | `--mn-caution` | `#8a5700`, предупреждение на светлом листе |
| Функция | `--mn-focus` | видимая сплошная обводка цвета `--mn-ink` |
| Функция | `--mn-on-ink` | `--mn-sheet`, текст на индиго |

Проверка этих пар на `--mn-sheet` даёт: ink 13.595:1, muted 6.02:1,
positive 6.51:1, danger 7.36:1, caution 5.74:1. На `--mn-paper` ink
12.679:1, body 11.382:1 и muted 5.615:1. Тонкий `--mn-rule` на бумаге
имеет лишь 1.55:1: это допустимо для декоративного разделителя, но для границы,
по которой узнаётся поле или состояние, нужен более контрастный токен и отдельная
проверка ≥3:1. Эти числа относятся к непрозрачным парам; наложения, текстуры,
hover и disabled проверяются по фактическим вычисленным цветам. Цвет никогда не
передаёт статус без текста, значка или иной различимой формы.

### Типографика, пространство и геометрия

| Роль | Правило |
|---|---|
| Display | Локальный Cormorant Garamond для латиницы/кириллицы, крупные editorial-заголовки; `Georgia, serif` fallback. Не применять к длинным инструкциям или вводу. |
| Reading/UI | Системный sans для текста, полей, кнопок, навигации и статусов. Это обеспечивает чтение разных письменностей без ещё одного обязательного шрифта. |
| Рубрика/folio | Системный mono для коротких номеров, дат, подзаголовков до одной-двух строк; не для инструкций или пользовательского материала. |
| Размеры | Базовый текст 16 px / line-height 1.5–1.7; поля не мельче 16 px; display через `clamp()` с проверкой реальных русских строк на 320 px и при 200% тексте. |
| Длина строк | Основной текст 55–75 символов на desktop; карточка задания/форма уже. Не сжимать ввод ради красивой симметрии. |
| Шаги | 4/8 px: `4, 8, 12, 16, 24, 32, 48, 64` как шкала. Отступ страницы mobile 18–24 px, desktop около 44 px; максимум ширины задаётся по типу страницы. |
| Геометрия | 1 px правила, почти прямые углы (0–2 px), 44–46 px удобная область нажатия. Тень только у действительно наложенного листа; не у каждого блока. |

Для production конвертировать имеющийся TTF в локальный WOFF2 с сохранением
кириллицы и латиницы, положить лицензию рядом и использовать `font-display: swap`.
Нельзя подменять фразы статичным изображением шрифта. Для CJK, арабского и других
письменностей проверять fallback, высоту строк и направление; утверждение о покрытии
всех языков Cormorant не делается. Пользовательский текст может содержать разные
письменности на одном экране. Язык интерфейса первого релиза — русский; подготовка
новых переводов требует явной locale-стратегии, а не набора CSS исключений.

### Плотность и композиция

- Лендинг: на desktop две неравные плоскости; слева читаемый заголовок, объяснение
  и действие, справа индиговый портретный panel. Выноски слегка перекрывают границу,
  но не закрывают лицо, заголовок и CTA. Три коротких смысловых ссылки идут после hero;
  ниже — разделы с реальными примерами материалов, упражнений и занятия.
- На mobile порядок: заголовок → смысл → primary action → гравюра → смысловые плитки.
  Горизонтальное наложение превращается в вертикальное; не компенсировать узость
  микрошрифтом. Шапка и футер существуют как нормальный поток страницы.
- Рабочие страницы: общий лист/фон, рубрика и заголовок, один главный action,
  строки/правила и локальные пояснения. Редактор материала desktop сохраняет разделение
  «документ / preview». Редактор упражнения — одна колонка на открытом листе:
  тип → большой пример/preview → шаги → список упражнений внизу; ни inspector, ни
  боковой preview, ни постоянный блок материала. Читаемая ширина текста ограничена,
  рамки-в-рамках заменены тонкими разделителями. На mobile панели идут последовательно
  без потери ввода и фокуса.
- Study: ограниченная ширина, спокойная поверхность вопроса, ясный reveal/submit,
  явное различие scheduled, replay и practice. Декор не мешает чтению, таймингу
  ответа, видео/аудио или клавиатурной навигации.

## Графика, иконки и медиа

Гравюра [Mnemosyne](../../design/prototype/assets/mnemosyne-engraving.png) —
сгенерированный оригинальный растровый master 1024×1536 на сплошном индиго.
[Происхождение](../../design/prototype/assets/mnemosyne-provenance.md) сохраняется
с asset. Лицо должно оставаться гармоничным и спокойным: без грустной мимики,
зрачков, пластиковой ретуши и потери штриховки. Не перерисовывать его автоматически
при каждом изменении страницы. Рядом допустимы редкие облака, звёзды и орбиты;
их положение подчинено композиции, а не анимации. Декор `aria-hidden`, без фокуса;
значимая подпись остаётся настоящим текстом. Гравюра получает краткий alt при
смысловой роли или пустой alt, если её смысл уже назван рядом. Обычная пользовательская
картинка получает содержательный alt по контексту материала.

PNG master прототипа (~2.3 MB) не отдавать каждому клиенту как единственный
production вариант. Сформировать версии AVIF/WebP и fallback по фактической
поддержке, сохранить пропорции/размер места до загрузки, сравнить качество лица,
штрихов и текстуры на 1×/2×. Для hero при доказанном LCP использовать приоритетную
загрузку; для изображений ниже первого экрана — lazy. Текст и действие доступны
раньше графики. Если нужен responsive `<img>`, проверить `NgOptimizedImage`,
`width`/`height`, `sizes` и `priority`; CSS background не должен прятать значимое
изображение и не получает эти оптимизации автоматически.

Иконки действий — единый лаконичный набор, размер и толщина штриха задаются токенами.
Предпочтительны подписанные кнопки; пиктограмма без текста допустима только при
однозначном действии и доступном имени. Кандидат для статичных SVG —
[Lucide](https://lucide.dev/) с [ISC/MIT notices](https://github.com/lucide-icons/lucide/blob/main/LICENSE):
выбирать конкретные SVG, фиксировать источник/версию и хранить лицензию, не
подключать icon-font, CDN или целую библиотеку ради нескольких символов. До принятия
конкретного набора допускаются уже существующие оригинальные простые знаки Mnema.
Новые зависимости требуют отдельного разрешения по AGENTS.md.

UI плееры, upload и пользовательские изображения наследуют палитру и focus/touch
правила, но медиа-функция важнее декора. Кнопки play/pause, mute, seek,
zoom/save и upload подписаны и проверены на клавиатуре; captions/транскрипт
показываются, когда данные доступны. Контрастные состояния и error/retry должны
работать и без загруженного preview. Не менять media API ради оформления.

## Компоненты, состояние и производительность

- Глобальны только токены, базовая типографика, focus/reset и небольшие primitives
  с общей семантикой (`PageHeading`, `PaperSurface`, `Action`, `Field`, `StatusNotice`,
  `EmptyState`). Локальные блоки `LandingHero`, `EngravingPanel`, `DeckRow`,
  `EditorPreview`, `StudyFrame` принадлежат своим маршрутам. Не создавать компонент
  с десятками флагов для всех «карточек» и не импортировать целиком прототиповый CSS.
- Standalone route components; первичные landing/login могут быть eager, редактор,
  авторинг, медиа и Study — lazy `loadComponent`/`loadChildren`. `@defer` применять
  к тяжёлым нижним секциям или рендерам после user intent, с полезным placeholder,
  loading и error. Не откладывать главный текст, CTA, вопрос или обязательное поле.
  Измерять зависимость начального bundle от импортов; синтаксис `@defer` сам по себе
  не гарантирует отдельный chunk.
- Colocated `signal` для локального UI state и `computed` для производных значений;
  API service остаётся владельцем сетевого обмена, сервер — фактов о сохранении,
  ревизии, прогрессе и правах. `effect` используется для внешних side effects, а не
  для копирования одного signal в другой. `OnPush` — типовой режим компонентов.
  Подписки имеют lifecycle boundary; формы не теряют ввод на navigation/error.
- Для каждого маршрута видимы начальная загрузка, пусто, данные, partial failure,
  ошибка с retry, pending mutation, конфликт и неподтверждённое сохранение там,
  где они возможны. Статусы названы словами, не только цветом или spinner. При
  route transition фокус переходит к заголовку, сохранение/диалог возвращает фокус
  предсказуемо. Никаких фальшивых данных, недействующих ссылок и «скоро» в главном CTA.
- Длинные списки используют ограниченные страницы; rich editor, Mermaid, YouTube
  и прочие тяжёлые возможности не попадают в landing bundle. Видео не autoplay.
  Декоративный слой статичен, не создаёт layout shift или долгую работу main thread.

## Общие примитивы: выбор, подсказка, шкала, акцентная кнопка

Четыре примитива лежат в `frontend/src/app/shared` (кнопка — в `global_styles.css`) и нужны
экранам ИИ-слоя (composer, билдер, paywall). Они не добавляют зависимостей, не ходят в сеть и
не знают о продуктовых экранах. Исследование и исходные сниппеты:
[UX ИИ-слоя](../reviews/ai-layer-research-2026-10/ux.md), разделы D.2, E и I.2.

### `app-segmented-choice` — выбор одного из немногих

- **Когда.** От двух до пяти коротких вариантов, где важно видеть все сразу (подробность, строгость
  проверки). Длинные или многословные варианты — обычная радиогруппа или `mnema-select`.
- **Доступность.** Это `fieldset` + `legend` + нативные `input[type=radio]` с одним `name`: стрелки,
  Space, Tab и имя группы даёт платформа. Невидимая радиокнопка перекрывает весь сегмент, поэтому цель
  нажатия не меньше `--mn-touch-min`. Выбранный сегмент отличается не только цветом: заливка, заполненная
  точка и инверсия текста; фокус рисуется на сегменте (`:has(:focus-visible)`).
- **Живое пояснение.** Под группой всегда есть `p[aria-live=polite]`; `fieldset` связан с ним через
  `aria-describedby`. Текст берётся из `hint` выбранного варианта и меняется вместе с выбором. Длинное
  объяснение — `app-toggletip`, который проецируется в строку сегментов.
- **Forced colors и узкий экран.** Границы, выбор (`Highlight`) и недоступность (`GrayText`) заданы системными
  цветами; сегменты переносятся на следующую строку, на 320 px растягиваются по ширине.
- **API.** `legend`, `options: {value, label, hint?, disabled?}[]`, `model` `value`, `name`, `disabled`.
- **Не делать.** Циклическую кнопку «переключатель уровней», вложенные радио в одной группе, подсказку
  только по hover.

### `app-toggletip` — «ⓘ» с коротким объяснением

- **Когда.** Пояснение, которое нужно не всем: «чем «Мягко» отличается от «Строго»». Всё, что ученик обязан
  прочитать (ошибка, ограничение), остаётся в потоке страницы.
- **Доступность.** Кнопка с `popovertarget` и именем «Подробнее: <тема>»; всплывающий блок — `popover="auto"`:
  Esc и клик вне закрывают его без скрипта, фокус остаётся на кнопке или возвращается к ней. Ничто не зависит
  от hover, содержимое — обычный проецируемый текст (допустима ссылка). Рядом с кнопкой блок ставит CSS anchor
  positioning; без него браузер центрирует блок в окне. Цель нажатия — `--mn-touch-min`.
- **Не делать.** Интерактивные формы внутри, несколько toggletip подряд, замену видимой подписи поля.

### `app-usage-meter` — шкала расхода, где главное — текст

- **Текст — источник истины.** Подпись и предложение под шкалой («Использовано 14 %, из них 3 % зарезервировано,
  хватит на ≈ 30 материалов, ещё 74 % откроется 4 октября, обновится 1 ноября.») содержат всё, что рисует полоса.
  Полоса `aria-hidden`, без `role="meter"`. Проценты и «≈» отбиваются неразрывным пробелом.
- **Что рисуется.** Сплошная часть — использовано; штриховка — резерв идущих партий; засечки — точки недельных
  разблокировок; мягкая область с пунктирной границей — ещё не открытая часть. Цвет не несёт смысл в одиночку.
- **Вход.** Только числа и уже отформатированные подписи, без HTTP. Соответствие `GET /api/usage`:
  `total` ← `credits.total`, `used` ← `credits.used`, `reserved` ← `credits.reserved`, `unlocked` ←
  `credits.unlocked`, `ticks` ← накопленные доли `weeklyUnlock.portions` от `total`, `remaining` — оценка
  в материалах, `resetsOn`/`nextUnlock` — даты. Процент в тексте считается, как `percentUsed` (использовано
  вместе с резервом, округление половины вверх). Значения вне диапазона обрезаются: отрицательные — 0, использованное
  и резерв не выходят за шкалу, засечки вне 0..1 отбрасываются.
- **Движение.** Нет; reduced motion обрабатывать не нужно. Forced colors: системные цвета и пунктирные рамки.
- **Не делать.** Две шкалы одного лимита, проценты без текста вокруг, анимацию заполнения.

### `.generate-cta` — кнопка со «змейкой»

- **Когда.** **Одна на экран**, только главное действие запуска ИИ («Создать» в composer, «Добавить упражнения»
  в билдере). Не добавлять к обычным `.primary`: приём перестаёт быть сигналом. Класс самодостаточный, его не
  сочетают с `.button`.
- **Движение.** Змейка бежит по рамке только при `:hover` и `:focus-visible`, ровно три круга по 1,6 с (≈ 4,8 с),
  затем остаётся статичный блик. Не запускается у `:disabled` и `[aria-disabled="true"]`: кнопка, которой не хватает
  лимита, остаётся нажимаемой (`aria-disabled`) и объясняет причину рядом.
- **Реализация.** `@property --mn-snake-angle` и `conic-gradient` на слое `border-box`; псевдоэлемент `::before`
  у `.button` занят волной. Анимация перерисовывает одну кнопку в main thread, поэтому приём допустим лишь
  для единичной кнопки.
- **Reduced motion и forced colors.** `prefers-reduced-motion: reduce` — без круга, статичный блик под углом 40°.
  `forced-colors: active` — градиент не вычисляется, рамка `ButtonText`, при hover/фокусе `Highlight`.
- **Проверка.** Контракт стилей закреплён тестом `generate-cta.css.spec.ts`; вид и движение — снимками
  в реальном браузере (desktop 1440, mobile 390, 200 % масштаб, reduced motion, forced colors).

Где показаны сейчас: выбор режима сравнения текстового ответа в редакторе упражнения (маршрут редактора
упражнения, поля «Допустимые ответы»): `app-segmented-choice` и `app-toggletip`. `app-usage-meter` и
`.generate-cta` подключат профиль и composer; до этого они проверены компонентными тестами.

## Движение, доступность, язык

Движение только объясняет смену состояния: hover/focus feedback или короткое
появление локального слоя. Никакого параллакса, вращающихся звёзд, бесконечной
анимации и движущейся текстуры. `prefers-reduced-motion: reduce` отключает плавную
прокрутку и нефункциональное движение; состояние остаётся понятным. Не задавать
глобальное `transition: all`. Анимация не должна блокировать ввод и может быть
прервана новым действием.

Цель — WCAG 2.2 AA. Использовать семантические header/nav/main/footer,
один h1 на экран, label и текст ошибки у поля, native control где возможен,
видимый фокус, skip link и логичный порядок Tab. Для обычного текста ≥4.5:1,
для крупного ≥3:1; значимые границы контролов/иконки ≥3:1. Проектная цель
области нажатия 44–46 CSS px; WCAG 2.2 AA 2.5.8 требует 24×24 px либо применимые
исключения/достаточное расстояние. Проверять 320 CSS px и 200% масштаб без
горизонтальной прокрутки, кроме содержимого, которому она нужна по смыслу
(например, широкая диаграмма). Не запрещать browser zoom. При forced colors
пользователь должен различать focus, selected, disabled и error.

Системные уведомления и ошибки — короткие, спокойные, с действием восстановления.
Тексты первого релиза русские; английские термины показываются, если это материал
пользователя или название стандарта. Переводимые строки не вшивать в SVG и PNG.
Учитывать длинные слова, смешанный LTR/RTL контент, даты и единицы через locale
форматирование. Текущий `I18nService` — факт реализации, а не основание обещать
готовые локализации. Выбор Angular i18n или продолжения локального механизма
требует отдельной оценки, особенно если меняются зависимости и runtime-switch.

## Приёмка каждой UI-поставки

| Область | Проверка и свидетельство |
|---|---|
| Сходство | Снимки маршрута на 1440, 768, 390 и 320 CSS px рядом с прототипом; фиксировать намеренные продуктовые отклонения. Не требовать пиксельного совпадения текста с английским референсом. |
| Функция | Пройти реальный путь вход → колода → материал/редактор → упражнение → занятие; проверить ссылки, back/close, pending, retry и сохранение без изменения API. |
| Контент | Длинный русский заголовок, длинное имя колоды, пустой список, пользовательский HTML как текст, языковая смесь, отсутствующий media asset; без overflow и перекрытий. |
| Доступность | Tab/Shift+Tab/Enter/Space, skip link, focus after route/dialog, names/status/errors; contrast по вычисленным цветам, 200% text, 320 px reflow, forced colors, reduced motion. Автоматическая проверка дополняется ручной. |
| Производительность | Сравнить route chunks и initial JS до/после, изображения/fonts по network transfer, LCP/INP/CLS на заявленном профиле устройства/сети. Для ориентиров использовать p75 LCP ≤2.5 s, INP ≤200 ms, CLS ≤0.1; измерение, не обещание. |
| Совместимость | Chromium и Safari/Firefox для ключевого пути; хотя бы одна проверка VoiceOver или TalkBack и реального touch до публичного запуска. Не выдавать desktop emulation за устройство. |
| Качество | Frontend lint/tests/build и полный репозиторный quality gate; component tests для критических состояний; screenshot/e2e проверка там, где риск визуальный. Никаких новых зависимостей без отдельного разрешения. |

Снимки и замеры помечать датой, commit SHA, viewport, браузером и сценарием.
Результат считается готовым, когда пользователь видит верную функцию в выбранной
идентике, а не когда CSS и тесты просто собираются.
