# Переход Mnema с Apache 2.0

## Решение

Новые официальные ревизии Mnema публикуются в открытом репозитории по
[`Mnema Source-Available License 1.0`](../../LICENSE):

- любой посетитель может просматривать публичный репозиторий и пользоваться
  функцией fork в пределах прав, отдельно предоставленных условиями GitHub;
- одно физическое лицо может бесплатно собирать, запускать и изменять код
  локально только для личного частного использования;
- использование организацией или в её интересах запрещено без отдельной
  письменной лицензии независимо от коммерческого статуса и источника
  финансирования;
- shared/public hosting, multi-user deployment, SaaS, managed service,
  коммерческое использование, распространение и machine-learning use запрещены
  без отдельной письменной лицензии;
- отдельные коммерческие, образовательные, исследовательские, пилотные,
  льготные или безвозмездные условия могут согласовываться индивидуально и не
  создают обязательства предложить такие же условия другим;
- hosted subscription и лицензия на исходный код являются разными договорами.

Канонический текст лицензии написан на английском. Для российской аудитории
поддерживается [`LICENSE.ru.md`](../../LICENSE.ru.md); в пределах, разрешённых
применимым правом, английский текст имеет приоритет. Применяется право Российской
Федерации.

Это source-available, а не Open Source: ограничения по сферам и способам
использования несовместимы с [Open Source Definition](https://opensource.org/osd).
Публичность GitHub отдельно разрешает пользователям просмотр и fork внутри
сервиса, но сама по себе не предоставляет права запускать, развёртывать,
распространять или коммерциализировать код
([GitHub Docs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)).

## Apache cut-off

Последний Apache 2.0-срез зафиксирован без переписывания истории:

- commit: `f4c37df69c143d67e478b6b84af575e94941ece2`;
- tag: `v1-apache-final`;
- исторический текст: [`LICENSES/Apache-2.0.txt`](../../LICENSES/Apache-2.0.txt).

Apache 2.0 предоставляет бессрочную и безотзывную copyright-лицензию, поэтому
уже полученные права на этот срез сохраняются
([Apache License 2.0, §2](https://www.apache.org/licenses/LICENSE-2.0.html)).
Новая лицензия не применяется к историческому срезу задним числом и не удаляет
существующие clones или forks. Владелец вправе публиковать свои последующие
ревизии на иных условиях, но любой пользователь может продолжать законно
использовать Apache-версию.

## Почему выбрана кастомная лицензия

Готовые source-available лицензии не закрывают принятую границу:

| Вариант | Несовпадение с решением Mnema |
|---|---|
| PolyForm Noncommercial / Strict | прямо разрешает использование образовательными, исследовательскими и государственными организациями |
| PolyForm Internal Use | прямо разрешает внутреннее организационное использование |
| Elastic License 2.0 | разрешает бесплатное внутреннее использование компаниями |
| FSL | ограничивает преимущественно competing use и переходит в Open Source через два года |
| BSL 1.1 | разрешает non-production use и требует будущий переход на Open Source-лицензию |
| AGPL | разрешает коммерческое использование при выполнении copyleft-условий |

Официальные тексты: [PolyForm](https://polyformproject.org/licenses),
[Elastic License 2.0](https://www.elastic.co/licensing/elastic-license/faq/),
[FSL](https://fair.io/licenses/) и [BSL 1.1](https://mariadb.com/bsl11/).

## Российская правовая конструкция

Лицензия сформулирована как безвозмездная простая лицензия, заключаемая в
упрощённом порядке по статье 1286.1 ГК РФ. Акцептом являются действия, требующие
предоставленных лицензией прав: воспроизведение, сборка, запуск или изменение.
Предмет, способы использования, весь мир, срок и ограничения указаны явно.

Ключевые основания:

- исходный и объектный код программы охраняются как литературное произведение
  ([ГК РФ 1261](https://www.consultant.ru/document/cons_doc_LAW_64629/ce1359ed5b9bd99896d7a496c7887e7c223a2cbc/));
- лицензиат получает только прямо указанные способы использования
  ([ГК РФ 1235](https://www.consultant.ru/document/cons_doc_LAW_64629/640cbca01ece35bc535ffe5e6d96b7988d2daf6b/));
- условия открытой лицензии должны быть доступны до использования, а акцепт
  может совершаться указанными в ней действиями
  ([ГК РФ 1286.1](https://www.consultant.ru/document/cons_doc_LAW_64629/e0c0d28fc67b7998751c3a7f98f6be9dfb789911/));
- идеи, методы, процессы и функциональность сами по себе авторским правом не
  охраняются
  ([ГК РФ 1259](https://www.consultant.ru/document/cons_doc_LAW_64629/be05678dc42ddc67aae5be9ba9beebd367fb9a3f/)).

Лицензия создаёт правовую границу против копирования и использования кода, но
не может запретить независимую реализацию идеи. Внутреннее нарушение также нужно
обнаружить и доказать; публичность исходников не даёт автоматического контроля
за чужой инфраструктурой.

## Contributions и Git identity

Публичные code contributions приостановлены до отдельного contributor
agreement. Issues с идеями, ошибками и UX-наблюдениями остаются открытыми.
Простого inbound=outbound недостаточно для модели, где владелец должен сохранять
право коммерческого перелицензирования чужого вклада.

История показывает две human Git identities владельца и автоматические
Dependabot contributions. Корпоративный email в commit metadata сам по себе не
определяет правообладателя, однако происхождение кода и границы трудовых
обязанностей должны быть подтверждены отдельно
([ГК РФ 1295](https://www.consultant.ru/document/cons_doc_LAW_64629/b131343c6f094841b1ed8c5e6db72a390ea3e11c/)).

Для новых коммитов repository-local personal identity является единственной
атрибуцией. Агенты не добавляют `Co-authored-by`, `Signed-off-by`,
`Generated-by`, `On-behalf-of` и аналогичные trailers без прямого запроса
пользователя.

## Brand и third-party boundary

Лицензия не предоставляет прав на имя, логотипы, домены и иные обозначения
Mnema; допустимое номинативное упоминание описано в
[`TRADEMARKS.md`](../../TRADEMARKS.md). Регистрация товарного знака является
отдельным действием и требует поиска тождественных и сходных обозначений.

Third-party dependencies, assets и bundled components сохраняют собственные
лицензии. Root license применяется только в пределах прав Лицензиара. Перед
коммерческим выпуском остаются обязательными provenance review, dependency
notice audit и финальная проверка текста российским IP-юристом.

## Применение и rollback

Cut-over должен применяться одним reviewable изменением: root license, перевод,
NOTICE, README, self-host runbooks, contribution policy, brand policy и
канонические product/operations документы обновляются вместе.

До merge безопасный rollback — закрыть PR и удалить feature branch отдельным
решением. После публикации новой версии уже выданная добросовестному лицензиату
лицензия не должна считаться отозванной задним числом; будущие версии можно
выпускать на новых условиях. Apache tag и историческая лицензия сохраняются при
любом дальнейшем решении.
