# LC-202 — Показывать границы проверенного материала

## Контекст и результат

Objective coverage уже существует, но нужен понятный learner-facing scope и отдельная
diagnostic история вариантов. Не вводить процент знания по числу упражнений.
Parent [LC-E2](../epics/representative-practice.md), [proposal R04](../proposal.md).

## Scope и ограничения

Сохранить distinct enabled objectives и state precedence. Уточнить material view:
какие цели введены/проверены, какие ещё не проверялись; объяснение ON_TRACK как расписания.
Variants presented/assessed за declared horizon — отдельный detail, no all-variants requirement.
Unknown legacy history не показывает 0 lifetime attempts. Criterion UUID разных rubrics
не объединяется автоматически. Новые shared elements сначала в styleguide.

Добавление парафраза существующей цели не меняет coverage, новая цель расширяет scope.
Enable/disable/head/private override/update учитываются существующим projection boundary.
Тексты понятны без внутренних таблиц и evaluator implementation details. Mobile/reflow,
keyboard/focus, screen-reader status semantics и reduced motion обязательны.

## Критерии приёмки

- [ ] Duplicate/add/remove paraphrase не меняет denominator/state, пока остаётся хотя бы одно enabled exercise на цель; удаление последнего корректно меняет active scope.
- [ ] New objective unknown; introduced/unassessed обычно LEARNING; restart due учитывается.
- [ ] ON_TRACK только при всех enabled introduced+assessed+level≥2+future due.
- [ ] Assisted/partial/replay диагностика не названа mastery, history horizon явно обозначен.
- [ ] Чужие/скрытые materials/rubrics не раскрываются; bounded read и pagination сохранены.
- [ ] Learner понимает scope через progressive disclosure, нет «выучено 2/20 упражнений».

## Проверка

Business-state matrix backend; shared progress fixtures и component tests critical logic;
real-browser 320/390/1440, keyboard и accessible labels/focus. Не утверждать real screen-reader
coverage по jsdom или DOM inspection. Full gate и visual evidence.

## Риски и rollback

Слишком много diagnostics перегружает UI; оставить один основной state и раскрываемый detail.
Rollback projection/UI version без удаления observations или learner progress.
