# LC-303 — Что делать при содержательной правке

## Решение и timebox

За 2–4ч определить authoring flow для редакционной правки, смены correct meaning,
нового skill и upstream update. Принятое правило «edit сохраняет state; restart явный»
не менять автоматически. Выход — сценарии, recommendation и next executable issue.

## Scope

Сравнить: оставить явный restart; предложить новую diagnostic проверку; создать новую
objective при действительно новом scope. Title match не доказательство semantic equivalence.
Каждый вариант проверяется на private overrides, community copies, disabled exercises,
pending snapshots/AI, aliases и сохранённой истории.

## Критерии результата

- [ ] Typo не сбрасывает progress, новая цель unknown, историческая оценка не приписана новому смыслу без основания.
- [ ] Learner/author видит последствия до изменения, scope и rollback понятны.
- [ ] Нет скрытого automatic reset/LLM semantic migration; решения остаются explicit и versioned.
- [ ] Rejected options/risks и 1–3-day next issue готовы; unresolved product choice не помечен Ready.

## Проверка и rollback

Сценарная таблица с expected observable outcomes, human review meaningful differences.
Это research, не DB rewrite. Никакой purge, legacy v1 allowlist или cross-deck mastery.
