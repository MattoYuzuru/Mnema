# LC-101 — Контракт минимальных наблюдений

## Контекст и результат

Exact exercise provenance исчезает с presentation. Добавить schema/fixtures минимальных
observations с различимыми attempt result, assistance, mode, revisions и completeness.
Source: [current model](../current-model.md), parent [LC-E1](../epics/observations.md).

## Scope и ограничения

Входит R01/R02 [proposal](../proposal.md): immutable event identity, epoch/order,
lineage/reuse scope, terminal outcomes, compensation/restart facts, policy versions,
unknown legacy values, TTL/account purge indexes. Новый raw text/quotes/media не хранятся.
Отдельный PRESENTATION_ISSUED record сохраняет выданные identity/revisions/mode/time
без result/evidence; он обязателен для presented-variant diagnostics после snapshot cleanup.
AI provenance включает strictness/policy/prompt и actual grader version либо явный unknown;
requested evaluator отличается от effective fallback и его reason.
Один owning module в Learning; existing receipt и StudyState остаются authoritative.
Новая Flyway migration только после актуального inventory. Нет нового datastore/dependency.

Не входит writer implementation, redefining evidence classes, model training, public analytics API.
Документировать consumer/export contract рядом с Study; это отдельные observations,
не новая canonical evidence для practice. Scoped AGENTS boundary обновить только с применением.

## Критерии приёмки

- [ ] Schema различает assessed/not-assessed/unavailable и nullable unknown, не кодирует отсутствие correctness как false.
- [ ] Exact issued и terminal exercise+revision+objective+epoch+mode+server time восстанавливаются без presentation join; issuance не считается assessment.
- [ ] Уникальность retry и компенсации задана constraints/fixtures; old epoch не смешивается с новым.
- [ ] Privacy fixture не содержит text/quotes/URL; retention/purge отражают принятую policy.
- [ ] Author/source copy identities не присваивают прогресс чужому learner.

## Проверка

Shared fixtures + migration/real-DB constraint tests; schema validation backend/frontend where exposed;
docs validator. Full gate по runbook до review/push; проверка fresh/pending migration numbers.

## Риски и rollback

Схема может сохранить лишние sensitive fields или неверно определить authority.
Stop при unresolved ownership/retention. Additive migration должна допускать прежний runtime;
rollback сохраняет таблицу и данные, не DROP. Synthetic restore/restart — disposable DB.

## Зависимости

Принятый scope proposal, актуальная lineage и последняя миграция Learning (V76 на 2026-10-19). Выход — schema+contract, затем LC-102.
