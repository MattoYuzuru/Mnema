# LC-102 — Атомарно записывать факты обучения

## Контекст и результат

Implement writer LC-101 в существующих terminal paths, включая asynchronous AI/fallback,
не меняя due/streak/baseline behavior. New observations доступны после snapshot cleanup.
Parent [LC-E1](../epics/observations.md), [proposal R01](../proposal.md).

## Scope и ограничения

Scheduled/practice/replay terminal attempts, cancel/unavailable/old epoch, server hints,
transcript/pair interactions, restart и dispute compensation. Server captures exact issued
revision и persisted mode; client не выбирает attribution/evidence. Observation insert
в terminal transaction; AI network call остаётся вне DB transaction. Repeated delivery
не создаёт нового learning event. Client SELF_CHECK reveal только explicit diagnostic,
его новый endpoint можно отложить, не объявляя server-observed.

PRESENTATION_ISSUED вставляется атомарно с новой presentation во всех режимах. Start/refill
retry не создаёт duplicate issuance; abandoned/expired issuance сохраняется как выдача,
без result и без доказательства просмотра. Cursor advance/event/issued snapshot согласованы.

Не входит новый grader, response re-evaluation, scheduler change, изменение community engagement.
Raw text и durable quotes не копируются в ledger. Observation delivery не означает прочтение.

## Критерии приёмки

- [ ] Exact attempt retry возвращает прежний outcome и одну observation; changed payload конфликтует.
- [ ] Parallel AI completion/self-check/expiry даёт ровно один terminal fact, losing result не записан как второй.
- [ ] PRACTICE/REPLAY сохраняют diagnostic result, но state/evidence/due/streak не изменяются.
- [ ] Observation write failure не оставляет accepted result без обязательной истории.
- [ ] Restart/late answer/dispute сохраняют epoch/compensation order, оригинальная history immutable.
- [ ] Copy/source edits сохраняют exact выданную identity; no text/token logging.

## Проверка

Real-DB transaction/concurrency/integration cases для всех mechanics и AI fallback;
до/после baseline state comparison. Existing shared fixtures и full gate.
Никаких timing-only assertions; fixed clock и controlled concurrent paths.

## Риски и rollback

Double events, receipt-first нарушение, deadlock с restart/purge. Ограничить запись
ссылками и существующим locking order. Stop при duplicate/missing terminal history.
Rollback writer admission для новых sessions согласован со schema; accepted events сохраняются.

## Зависимости

LC-101. Выход нужен LC-103 и LC-201; не ждать classifier spike.
