# Вехи на горячем пути занятия (OB-301)

Что добавляет запись вех `FIRST_SESSION` и `TWO_DAYS` к завершению занятия
(`StudySessionRepository.complete`, `AttemptRepository.completeSessionIfTerminal`). Измерение — real-DB тест
`MilestoneHotPathIntegrationTest` (Testcontainers PostgreSQL, JDK 25, Colima), 300 итераций после 100 прогревочных, аккаунт с
2000 завершёнными занятиями; число выражений считается на JDBC-соединении и **проверяется** тестом, времена — нет (машина
без нагрузки; во время полного gate примерно вдвое медленнее).

## Добавочные выражения и время

| Случай | Выражений | Медиана | p95 |
|---|---|---|---|
| REPLAY | 0 | ≈ 0 | ≈ 0 |
| Обе вехи уже достигнуты (установившийся режим) | 1 (чтение по PK) | 0,26 мс | 0,35 мс |
| Второго дня ещё нет, все 2000 занятий сегодня | 2 | 0,65 мс | 0,93 мс |
| Первое завершение, 400 учебных дней | 4 | 1,05 мс | 1,5 мс |
| Для масштаба: существующий `DeckEngagement.studied` | 1 | 0,30 мс | 0,67 мс |

Вся первая транзакция с двумя уведомлениями `PATH_MILESTONE` в `beforeCommit` — ≈ 4,0 мс (p95 4,5 мс), 14 выражений;
это разовая цена первого занятия аккаунта. После достижения обеих вех добавка — одно чтение по первичному ключу
`account_milestone` (≈ 0,26 мс), сравнимо с уже существующей записью engagement.

## Планы (`EXPLAIN (ANALYZE, BUFFERS)`)

| Выражение | План | Время |
|---|---|---|
| Проверка достигнутых (`account_id`, `milestone_key IN (…)`) | Index Scan по PK, 2 buffer hits | 0,02 мс |
| Upsert, веха уже достигнута или прогресс не растёт | 0 строк записано | 0,03–0,04 мс |
| Upsert, новая строка или рост | 1 строка | 0,02 мс |
| Проба второго дня (`EXISTS` по `study_session`) | найдено сразу 0,01 мс; не найдено среди 2000 строк 0,15 мс | — |
| Чтение «Пути» для `GET /api/onboarding` | Index Scan по PK | 0,01 мс |

Оговорка: на таблице `study_session` в 100k строк планировщик выбирает для пробы seq scan; тест принудительно показывает
индексный план (`study_session_resume`, префикс `account_id`), времена в обоих случаях близки — доминирует round trip.
Проба выполняется только пока `TWO_DAYS` не достигнута.

## Вывод

Критерий OB-301 «горячий путь: измерено добавочное время» выполнен: в установившемся режиме +1 PK-чтение на завершение
занятия, на ответы (попытки) запись вех не добавляет ничего, кроме `AI_EXPLANATION` для ответа, проверенного
`ai-semantic` (один upsert). Существующие тесты Study зелёные в полном gate.
