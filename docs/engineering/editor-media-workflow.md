# Медиа в редакторе LearningItem

Эта реализация следует [Epic #76 refinement](epic-76-refinement.md) и
[upload transport](media-upload-transport.md). Редактор хранит в native node
только логический `assetId`; подписанный URL и объектный ключ в документ не
попадают. `DraftService` извлекает ссылки только из поддерживаемых native v1
image/audio/video nodes и заменяет `draft_media_ref` в той же транзакции, где
сохраняет JSON и row version. Ошибка ACL, CAS или лимита откатывает и документ,
и прежние holds. Истёкшие черновики не удерживают asset логически; при их
физическом удалении и при обычном delete строки holds снимаются через FK cascade;
исторические опубликованные revisions удерживают их отдельно.

Файловый picker, drag-and-drop, кнопка системной камеры и запись через
`MediaRecorder` ведут в одну ограниченную очередь. Drop служит дополнением к
доступному с клавиатуры picker. Браузерный MIME — декларация для admission,
а не доказательство типа файла: после передачи сервер проверяет байты и codec.
Кнопка «Вставить» доступна после получения `assetId`, поэтому публикация может
обогнать `READY`. Автор затем задаёт alt/title и вставляет node через native
editor. В Browse/Study pending/failed состояния отображаются отдельно; правила
Study описаны в refinement.

Передача: две параллельные задачи в одной вкладке, внутри каждого multipart
части идут последовательно и запрашивают подписанные URL пачками до 16. Это
клиентский предел; сервер отдельно применяет owner quota из
`MediaUploadSettings`. Состояние пары `state` (транспорт) и `assetState`
(проверка/обработка) не смешивается. `GET /media-assets/{assetId}/upload`
опрашивается только пока вкладка видима, начиная с 2 секунд и с backoff до
15 секунд при неизменном статусе; возврат фокуса/сети вызывает немедленную
проверку. Таймеры и слушатели прекращаются при выходе из редактора.

При SPA-переходе из опубликованного редактора уже начатая передача байтов
завершается, даже если страница редактора уничтожена. Полная перезагрузка
браузера не сохраняет байты локального файла. Серверный черновик сохраняет
`assetId` и место вставки; автор выбирает файл повторно. Multipart получает
список уже принятых частей, single PUT — свежую owner-scoped ссылку. Когда
обработка завершится, открытую страницу материала обновляет viewer #239.
Конфликт свежего серверного черновика не заменяет грязный локальный ввод:
редактор требует явного выбора версии.

Отмена прерывает текущий XHR и просит сервер остановить текущую generation;
поздняя PUT ссылка остаётся действительна до TTL, поэтому cleanup ждёт
`issued_until` и grace. Для `REJECTED`/`FAILED_RETRYABLE` повторная попытка
использует тот же assetId и новую generation. Неизвестный исход finalize
проверяется статусом и повторяется с тем же command ID, пока вкладка жива.
После reload состояние `FINALIZING` ожидается через статус вместо отправки
нового command ID.

Скрипты и build не отправляют файлы за пределы локальной среды. Для реальной
проверки браузерного пути нужны авторизованный Learning API и browser-reachable
MinIO с CORS для текущего origin. У Yandex остаётся отдельная parity проверка
подписанного `Content-Length`, CORS и CopyObject до внешнего запуска.
