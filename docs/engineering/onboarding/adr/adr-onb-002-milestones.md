# ADR-ONB-002 — «Путь» как реестр фактов, а не движок достижений

## Контекст

Владелец хочет чек-лист освоения, прогресс-бары, тосты «вы сделали X», поддержку повторного
прохождения и «возможно, achievements API». Чек-лист должен быть верен для давних пользователей,
работать на нескольких устройствах и не ломать горячие пути (занятие, копия).

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Вычислять вехи на чтении (EXISTS-запросы по доменным таблицам) | Нет новой таблицы, всегда верно | 13 разных запросов на каждый GET, часть фактов теряется retention (presentations, AI-попытки), нет момента «достигнуто» для тоста |
| B. Клиент отмечает выполненное | Просто | Неверно между устройствами, подделывается, не видит действий вне тура |
| **C. Ledger `account_milestone`, синхронный upsert в транзакции события + backfill** | Один PK-запрос на чтение, точный момент для уведомления, переживает retention, повторы безопасны | Точки вызова в нескольких доменных writers; нужно дисциплинированно добавлять новые |
| D. Общий event bus + асинхронный потребитель | Слабая связность | В Learning нет такой шины; лаг, гонки, второй канал доставки — оверинжиниринг |
| E. Универсальный движок достижений (правила, очки, уровни) | Гибкость | Нет требований; риск геймификации, которую продуктовые документы прямо отвергают |

## Решение (принято владельцем 2026-10-14)

C. Закрытый реестр вех (enum + фикстура контракта), `MilestoneRecorder` с `@Transactional(MANDATORY)`,
уведомление `PATH_MILESTONE` через существующий `NotificationPublisher` в той же транзакции,
bounded backfill по истории с `source=BACKFILL` без уведомлений.

«Достижения» в будущем = новые ключи того же реестра с тем же writer. Очки, уровни, рейтинги
и публичные значки не вводятся без отдельного продуктового решения.

## Последствия

- Добавление новой фичи, которая должна быть вехой, требует вызова recorder в её writer и строки
  в фикстуре; inventory-тест сверяет реестр с фикстурой и с точками вызова.
- Учебная колода засчитывает «Первую колоду» и «Первое занятие», но не авторские вехи
  (`purpose=USER` в условиях), чтобы «Путь» учил делать своё.
- Перепрохождение тура не сбрасывает факты; сброс «Пути» не предусмотрен (это история действий).
- Удаление аккаунта удаляет строки (#409).

## Проверка

Real-DB тесты конкурентных повторов, точной однократности уведомления, отката вехи вместе с
откатом действия, backfill идемпотентности и отсутствия вех для практики/повтора/чужих копий.
