# ADR-ONB-005 — Награда за полный «Путь»

## Контекст

Идея владельца: за 100 % «Пути» — персональный промокод −10 % на подписку, 24 часа. Промокоды
сейчас выдаёт только admin-scope ([AI layer](../../../product/ai-layer-2026-10.md)); выдачи по
событию нет. Риски: искусственная срочность (dark pattern), фарм
аккаунтов, вехи с тратой ИИ ради галочки, налоговый/юридический статус скидки.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Нет награды; поздравление | Ноль риска | Нет монетизационного «толчка» |
| **B. Системная выдача персонального кода по кампании владельца** | Переиспользует ledger промокодов, анти-фрод и кабинет; владелец управляет условиями | Новый путь выдачи, юридическая проверка текста |
| C. Общий код в тексте поздравления | Просто | Утечка кода, нет «одна на аккаунт» |

## Решение (принято владельцем 2026-10-14)

B (владелец 2026-10-14: делать; 7 дней, не 24 часа). Владелец создаёт кампанию типа `PATH_REWARD`
(скидка % до даты или тир на N дней) в кабинете; после достижения последней видимой вехи сервер
(при чтении «Пути», см. Implementation notes) создаёт `onboarding_reward(account_id PK, campaign_id, promo_code_id,
issued_at, expires_at)` и персональный код через существующий сервис промокодов, публикует
уведомление `PATH_REWARD_READY`. Только verified account (`mnema_trusted`), одна награда на аккаунт,
kill switch. Срок — 7 дней с момента выдачи, конкретная дата окончания текстом, без обратного отсчёта
в секундах; перепрохождение знакомства повторно не выдаёт (`UNIQUE(account_id)`).

## Последствия

- Набор вех, необходимых для 100 %, не должен требовать платного ИИ сверх Free.
- Текст кампании и условия — через юриста (реклама, защита прав потребителей).
- Метрика — конверсия и retention у получивших против holdout, не число выданных кодов.

## Проверка

Гонка двух последних вех даёт один код; неverified аккаунт не получает; выключенная кампания не
выдаёт; удаление аккаунта; аудит выдачи в кабинете.

## Implementation notes

Механика выдачи, как она реализована:

- **Не в транзакции последней вехи, а при чтении «Пути».** `mnema_trusted` — сигнал запроса Identity; последняя веха часто достигается в фоновом
  worker (проверка ИИ, распознавание) без сигналов, а новый аккаунт обычно проходит «Путь» раньше, чем станет trusted (3 дня), — выдача только в
  транзакции вехи отказала бы ему навсегда. Поэтому выдаёт `GET /api/onboarding` (клиент перечитывает его после каждого `PATH_MILESTONE`): до
  транзакции чтения, отдельной транзакцией под advisory-lock аккаунта с пересчётом вех; ошибка выдачи не ломает чтение. «Гонка последних вех даёт
  один код» обеспечивают lock и `UNIQUE(account_id)`.
- **Кампания** — `promo_campaign` (V76): создаётся выключенной, условия неизменны, включена не больше одной; глобальный выключатель
  `learning.onboarding.reward.enabled`, дневной лимит выдач `daily-limit`. Код — `promo_code` с `recipient_id`: погасить может только получатель;
  открытый код не хранится (выводится HMAC из id кода). Подробно — [architecture §7](../architecture.md#7-ритм-и-награда).
