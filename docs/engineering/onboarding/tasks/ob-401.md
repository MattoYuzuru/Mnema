# OB-401 — Недельный ритм

## Контекст и результат

Результат: вычисление ритма недели из `study_session`, `weeks_met`/`last_met_week` в journey,
веха RHYTHM_WEEK, блок на экране завершения занятия, семь точек недели и цель в профиле, тихий
тост при выполнении цели ([ADR-ONB-004](../adr/adr-onb-004-rhythm.md), architecture §7).

## Scope и ограничения

- Завершённые занятия SCHEDULED и PRACTICE (Q11), REPLAY — нет; разные `local_study_date`, ISO-неделя с
  понедельника. Обновить формулировки exercise catalog/Study: ритм — статистика, practice по-прежнему
  без canonical credit.
- Индекс для диапазона — только после проверки существующих индексов `study_session`.
- Тексты без потерь и долга; не в шапке; reduced motion на поздравлении.
- `weeksMet` показывается только в профиле (Q07).

## Критерии приёмки

- [x] Практика в новый день засчитывается; повторное занятие того же дня и REPLAY ритм не меняют. — `WeeklyRhythmIntegrationTest` (practice, same day, replay, ACTIVE), [S4](../../evidence/onboarding/ob-e4/handoff-session-4.md)
- [x] Граница недели и смена часового пояса покрыты тестами. — `WeeklyRhythmIntegrationTest` (воскресенье/понедельник, смена `zoneinfo`, невалидный пояс → UTC); даты — из сохранённой `local_study_date` и часов БД
- [x] `weeksMet` увеличивается один раз на неделю при гонке. — `WeeklyRhythmIntegrationTest` (две гонки и шесть потоков → +1; без advisory-lock 3 теста падают), поздняя прошлая неделя не считается
- [x] Экран итогов и профиль показывают одинаковое значение. — один источник (`JourneyStore`/`rhythm`), specs `rhythm-summary`, `profile-rhythm`, `study-session-page`; браузер — этап `onboarding_rhythm` harness ([S4](../../evidence/onboarding/ob-e4/handoff-session-4.md))

## Проверка

Real-DB integration, component tests, full gate.
