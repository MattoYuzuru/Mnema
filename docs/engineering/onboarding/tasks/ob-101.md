# OB-101 — Контракт, схема и API journey

## Контекст и результат

Состояние тура должно переживать перезагрузку и смену устройства, быть идемпотентным и не
мешать основным действиям. Результат: `contracts/onboarding/` (README + JSON фикстуры),
миграция `onboarding_journey`, `GET /api/onboarding`, `PUT /api/onboarding/journey`,
`PUT /api/onboarding/preferences` в Learning ([architecture](../architecture.md) §3–4).

## Scope и ограничения

- Пакет `app.mnema.learning.onboarding`; стиль контрактов как у usage/community: decimal-string
  версии, strong ETag, RFC 9457, `commandId` + `rowVersion`, 412 `VERSION_CONFLICT`.
- Eligibility: `learning.onboarding.eligible-from` и отсутствие своих колод; выключатель
  `learning.onboarding.enabled`. Состояния и переходы — таблица в контракте, недопустимый переход 409.
- В ответе пока пустые `milestones`/`rhythm`/`sampleDeck` (заполнят OB-301/401/201) — поля описаны
  сразу, чтобы клиент не менял форму.
- Миграция additive, номер — после сверки inventory с актуальным main. Purge аккаунта: TODO по
  образцу `deck_engagement_account` с владельцем #409.
- Нет новых зависимостей; Virtual Threads/конфигурация — как у соседних контроллеров.

## Критерии приёмки

- [ ] Первый GET eligible аккаунта создаёт ровно одну строку при параллельных запросах.
- [ ] Все переходы, включая UNDO_FINISH и REPLAY (увеличивает `replay_count`), покрыты фикстурами.
- [ ] Повтор `commandId` возвращает тот же ответ; устаревший `rowVersion` — 412.
- [ ] Не eligible аккаунт получает `eligible=false` без строки; выключатель off — то же.
- [ ] Контрактный тест frontend читает те же фикстуры.

## Проверка

Real-DB integration tests (Testcontainers), контрактные фикстуры, MockMvc/HTTP slice;
full backend gate по runbook.

## Риски и rollback

Неверная eligibility покажет тур старым пользователям — тесты границы даты. Rollback: флаг off;
таблица остаётся.

## Зависимости

Интеграция эпиков Сообщества 3–4 в рабочую базу (номера миграций). Блокирует OB-103/104, OB-201, OB-301.
