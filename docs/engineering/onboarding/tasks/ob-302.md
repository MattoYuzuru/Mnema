# OB-302 — Backfill вех по истории

## Контекст и результат

Давний пользователь должен увидеть уже освоенное. Результат: фоновая задача по существующему
фреймворку jobs, проходящая аккаунты батчами и записывающая вехи `source=BACKFILL` без уведомлений.

## Scope и ограничения

- По одной `INSERT … SELECT … ON CONFLICT DO NOTHING` на веху и батч; slice ограничен по времени,
  advisory lock как у `CatalogRank`; повторный запуск идемпотентен; dedupe key задачи по версии реестра.
- Вехи, факт которых не восстанавливается (retention presentations, отсутствие логов голоса),
  остаются невыполненными; это записано в контракте.
- Выключатель `learning.jobs.onboarding.backfill.enabled`; метрики числа строк и длительности.

## Критерии приёмки

- [x] Повторный запуск не меняет таблицу; прерванный продолжает с места. — `OnboardingBackfillJobIntegrationTest`, [backfill](../../evidence/onboarding/ob-e3/backfill.md)
- [x] План запросов индексный (EXPLAIN в evidence) на синтетике H. — планы проверяет тест (ни одного `Seq Scan` при `enable_seqscan=off`), синтетика 3000 аккаунтов, не объём H; время на H — экстраполяция в [backfill](../../evidence/onboarding/ob-e3/backfill.md)
- [x] Нет уведомлений для BACKFILL; LIVE после backfill работает как обычно. — `aRunTwiceChangesNothing…AndNothingIsAnnounced`, `OnboardingBackfillSemanticsIntegrationTest`

## Проверка

Real-DB integration на синтетике, EXPLAIN, full gate.
